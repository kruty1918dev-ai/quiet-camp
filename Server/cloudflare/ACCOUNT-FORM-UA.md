# Оформлення сторінок акаунта — 2026-10-24

Сторінки `/v1/cloud/delete-account` та `/v1/cloud/login` використовують єдине
оформлення Quiet Camp: темний зелений фон, кремова типографіка, адаптивна картка,
кнопки Google/Facebook і посилання на сайт, допомогу та політику.

Видалення проходить у два кроки: перевірка провайдера, потім підтвердження.
Кнопка видалення спочатку має `hidden disabled`; явне CSS-правило `[hidden]`
не дозволяє стилю кнопок показувати прихований елемент. Після входу показується
email/ім'я обраного акаунта через `textContent`. Скасування системного
підтвердження не надсилає запиту. Під час запиту кнопки блокуються; зміна
акаунта та невдала спроба видалення скидають локальну ідентичність і вимагають
повторного входу. Помилка мережі повідомляє, що результат не підтверджений.

Серверна перевірка свіжого Firebase ID token та Origin залишається обов'язковою.
Збережені Google `prompt:select_account`, одноразовий handoff із кодом,
скасування входу й `pagehide` beacon. Не додаються аналітика, зовнішні шрифти
чи зображення. CSP із nonce та `no-store` збережені. Службова форма має
`noindex`; для пошуку використовується публічна сторінка
https://oleksiy-havryliuk.de/quiet-camp/delete-account.

Обидва TextDecoder явно задають `ignoreBOM:false` (стандартне значення),
щоб поточні типи редактора Cloudflare приймали параметри конструктора.

## Перевірка

З каталогу `Server/cloudflare`:

```sh
npm ci
npm test
python3 test/ui-browser.py
```

Для браузерного тесту потрібні Python Playwright і Chromium за шляхом
`/usr/bin/chromium`. Папку з кадрами/JSON можна задати через `QC_UI_ARTIFACTS`.
Тест запускає локальний сервер із синтетичною конфігурацією, підміняє модулі
Firebase та відповіді API. Він не входить у справжній акаунт і не видаляє дані.
Перевіряє desktop/mobile, початкове приховування, помилки popup/SDK,
Google account chooser, повторні кліки, зміну акаунта, відмову від підтвердження,
успіх/помилку видалення, handoff і скасування входу. Реальні Google/Facebook
popup та видалення production-акаунта цим тестом не підтверджені.

## Публікація

Git push не підтверджує розгортання Worker. Для цього потрібна авторизація
в Cloudflare. У середовищі цієї правки `wrangler whoami` повернув
`You are not authenticated`.

Для ручної публікації збережіть чинні bindings/variables/secrets Worker
`quietcamp-access`; замініть лише код актуальним bundled `worker-dashboard.mjs`
і натисніть Deploy. Не створюйте нову D1 та не запускайте повторно міграції.
Не використовуйте старі bundled-файли: поточна версія зібрана з main після
оновлення Google/Facebook auth. Значення секретів у bundle не включаються.

Для збірки bundle з кореня репозиторію:

```sh
Server/cloudflare/node_modules/.bin/esbuild Server/cloudflare/src/index.mjs --bundle --format=esm --platform=browser --target=es2022 --outfile=worker-dashboard.mjs
```

Після розгортання відкрийте форму в приватному вікні: нове оформлення, дві
кнопки входу, жодної кнопки видалення до входу. Реальний OAuth перевіряйте
лише власним тестовим акаунтом; не підтверджуйте видалення робочих даних.
