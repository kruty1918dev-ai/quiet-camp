Перероби перший запуск Quiet Camp. Користувач відхилив нинішню довгу послідовність опитувань і її оформлення. Потрібна реалізація у грі, а не лише макет чи план.

Бажаний шлях: ОДНЕ запитання про вікову групу → вибір Google / Facebook / «Грати без входу» → звичайний шлях до гри. Максимум два екрани першого запуску для гравця, якому дозволений вхід. Вікові обмеження зберегти; якщо вхід для обраної групи недоступний, перейти до локальної гри без додаткового опитування.

1. Прибери майстер опитування
- Окремі екрани «Конфіденційність: Так/Ні», «Увімкнути добровільні відеобонуси?», Analytics, звіти про збої та «Можемо починати?» прибрати з обов’язкового першого запуску.
- Не ставити послідовно «18?», «16?», «13?». Не показувати підсумковий список увімкнених сервісів.
- Політика доступна за текстовим посиланням на обох екранах і в налаштуваннях. Повний текст відкривається лише за запитом, має зрозуміле повернення до попереднього стану й працює з bundled-копією без інтернету.
- Відображення політики та її версії — інформування, не згода на відстеження. Не писати «Продовжуючи, ви погоджуєтесь на всі сервіси».

2. Один нейтральний екран віку
Заголовок: «Ваша вікова група».
Пояснення: «Оберіть вікову групу для відповідних налаштувань гри».
Чотири однаково оформлені варіанти: «До 13», «13–15», «16–17», «18 і більше». Без попереднього вибору, підказок про вигоди старшого віку чи виділення 18+. Не збирати дату народження, документи чи батьківські дані. Якщо є можливість не відповідати, це Unknown із чинними обмеженнями.
Одне натискання обирає групу, надійно зберігає її й переходить далі; окремого підтвердження віку не потрібно. При помилці збереження залишити цей екран із короткою помилкою та повтором, не видавати успіх чи дозволи. Не перезапитувати відому валідну групу при кожному запуску.

3. Екран акаунта
Заголовок: «Збережіть свій табір».
Пояснення: «Увійдіть, щоб відновити прогрес на іншому пристрої».
Повнорозмірні кнопки з правильними іконками: «Продовжити з Google», «Продовжити з Facebook»; нижче помітна доступна дія «Грати без входу».
Підпис: «Без входу прогрес зберігається на цьому пристрої».
Провайдери доступні лише за реальних конфігурації та вікової допустимості. Не створювати guest cloud account. Для користувача зі збереженою сесією використати чинний шлях відновлення, без повторного вибору акаунта на кожному запуску. Без мережі або після скасування входу залишити можливість локальної гри.
Зберегти поточні Google account chooser, системний браузер/Firebase, одноразовий код зв’язування, login-cancel, відновлення профілю, конфлікти збережень і відмову від прив’язки зайнятого профілю. Жодних X/Apple-кнопок.

4. Стиль і верстка
Використай наявний BootCamp-фон/сцену, не переробляй світ чи рівні.
Палітра: лісовий #17382d / #132e25, кремовий #f6efdf, приглушений зелений #bdcbbd, теплий акцент #ddbf86. Залиш наявний шрифт гри з коректними uk/en/de-гліфами.
Одна цілісна компактна панель у нижній або середній безпечній частині екрана; текст, варіанти й дії всередині неї. Панель має достатньо непрозорий фон для контрасту. Не залишай білий текст на деталізованих наметах і багатті. Не відривай кнопки від пояснення порожнім простором на пів екрана. Уникай товстої рамки на весь екран, випадкових кремових прямокутників та іконок без зрозумілих підписів.
Ширина приблизно 88–92% безпечної області, на планшеті обмежена; внутрішні відступи 20–24 dp, проміжки 12–16 dp, радіус 18–22 dp. Орієнтир: заголовок 24–28 sp, основний текст 15–17 sp, кнопки щонайменше 48 dp; перевір реальні одиниці Canvas/UnityHTML замість механічного перенесення CSS px.
Вік — зручна сітка 2×2 або вертикальний список для великого тексту. Кнопки провайдерів — вертикально. Врахувати SafeArea, вирізи, короткі дисплеї, альбомну орієнтацію, планшети, перенесення німецьких підписів, масштабування тексту та Reduce Motion. Не додавати ресурсоємних blur/постефектів або непідтримуваного web CSS.
Перевір фактичний layout: батьківські flex/size, повторний mount, правила класів і координати дій. Приклад із браузера не доводить правильності рендера UnityHTML у Game View.

5. Відеовинагороди без стартового опитування
Не запитувати загальний дозвіл «увімкнути відеобонуси». Гравець замовляє конкретний перегляд зрозумілою кнопкою, наприклад «Відео → +1 життя». Не вмикати Analytics, Crashlytics чи персоналізацію натисканням цієї кнопки.
Перероби залежності optionalVideoBonuses / AdvertisingAllowed так, щоб відсутність старого стартового дозволу не ламала відео, але й не обходила UMP, вікові перевірки, Pro та закриті production/review gates. Не використовуй advertisingConsent=true як підробку згоди Google. За наявності старої явної відмови не перетвори її на дозвіл під час міграції; новий запит гравця проходить актуальний consent-flow.
Для дозволеної вікової групи оновлюй UMP-стан за поточною документацією Google; оновлення стану може бути фоновим, без стартової форми. Потрібну форму Google показувати при запиті відео, до рекламного запиту. Перевіряти CanRequestAds та належні сигнали цілей/режимів, не покладатися лише на локальний кеш. Після відмови, помилки чи скасування не надавати неотриманий дозвіл або винагороду; базова гра лишається доступною. Зберегти Privacy options у налаштуваннях, де потрібно. Не робити consent-form при кожному перегляді, якщо актуальний стан цього не потребує.
Не додавати автоматичну рекламу на запуску чи нові рекламні формати.
Analytics і Crashlytics залишити вимкненими на першому запуску; окремі дозволи можливі за бажанням у налаштуваннях, тільки якщо сервіс доступний і його конфігурація схвалена.
