# Бонусні відгалуження мапи

Після галявин 10, 20 і 30 розміщені три окремі заготовки: «Росистий берег», «Бурштиновий струмок» і «Галявина світлячків». Вони мають бічну стежку, власну мінідіораму, теплу картку та екран прев'ю з умовами відкриття. Основні 30 рівнів зберігають свої ID, нумерацію та порядок; бонуси не є обов'язковими для переходу далі.

## Умови й публікація

Конфігурація: `QuietCamp/Assets/QuietCamp/Resources/QuietCamp/bonus_camps.json`.

| Поле | Призначення |
| --- | --- |
| `id` | Стабільний ключ бонусного слота, також ключ майбутнього entitlement adapter |
| `afterLevel` | Бічне відгалуження після 10, 20 або 30; не індекс основного рівня |
| `requiredCompletions` | Кількість унікальних завершень відповідної десятки, 0–10; зараз 10 |
| `requiresPremium` | Чи потрібен додатковий підтверджений доступ; зараз false |
| `levelId` | ID опублікованого authored рівня. Порожнє значення означає заготовку |
| `theme` | `dew`, `amber` або `fireflies` для малюнка мапи й прев'ю |
| `titleKey`, `descriptionKey` | Ключі локалізації uk/en/de |

Доступ визначає `BonusCampAccessService`, читаючи наявний `ProgressionService`. Завершення тестових, сторонніх, бонусних або повторне проходження того самого рівня не заповнює умову десятки. Окреме збереження чи міграція для цих заготовок не потрібні.

Стани:

- `Locked`: ще не виконані умови; прев'ю відкривається, старт вимкнений.
- `ComingSoon`: умови виконані, але рівень ще не опублікований; показуємо «Незабаром».
- `Available`: виконані умови, заданий `levelId` і є відповідний ресурс; старт доступний.
- `Completed`: доступний бонус уже пройдений; можна переграти, на мапі є позначка завершення.

Поточні три слоти мають порожній `levelId`, тому вони не запускають підставні рівні. UI прямо пояснює, що контент готується. SDK оплати й рекламні пропозиції тут не додані.

Для майбутнього преміум-доступу виставити `requiresPremium: true` й підключити `GameServices.BonusEntitlement`: функція отримує `id` слота і повертає підтверджений стан доступу від вашого провайдера. Без адаптера доступ false; кліки на прев'ю його не видають. Якщо потрібен тільки преміум-доступ, `requiredCompletions` задається як 0.

Щоб опублікувати справжній бонус, створити окремий validated рівень у `Resources/QuietCamp/Levels`, наприклад `QC_BONUS001.json`, і задати той самий ID у `levelId`. Не вставляти його у `mvpLevelIds` чи `generatedLevelIds`: це змінить порядок кампанії. Додати рівень до перевірок solver/validator, перевірити проходження, збереження, альбом і повернення до мапи. Формат умов уже готовий, а самі три головоломки потрібно авторувати окремо.

## Геометрія та витрати

`RoadmapLayout` задає ті самі координати для арту, кнопок і автоматичного scroll до поточного основного рівня. Додаткові проміжки не змінюють порядкові номери. Перехід до прев'ю фіксує scroll; повернення відновлює його.

Малюнок бонусів входить у спільний mesh мапи. Прев'ю — один додатковий `MaskableGraphic` тільки в його відкритому вікні. Немає окремих камер, RenderTexture, завантаження сцен, генерації чи solver при прокручуванні. Графіка зібрана процедурно з тієї самої проєкції та палітри, що й основні мінігалявини.

Перевірки: `BonusCampTests` — каталог, умови, entitlement, відсутність впливу на кампанію й координати; `BonusRoadmapPlayModeTests` — натискання з raycast, три слоти, три формати, uk/en/de 130%, прев'ю, межі тексту, блокування відсутнього контенту та відновлення scroll. Нові player-білди дозволені лише за прямим запитом користувача.
