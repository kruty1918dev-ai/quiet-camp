# Адаптивний гід

Гід пояснює поточний стан табору, а не вимагає повторення еталонного рішення. Джерело правил — `RuleEvaluator` і `CampWalkability`. `PlacementGuidance.Explain` перетворює їхні докази на підказку; `TutorialDirector.Cue(CampSession)` вибирає наступну дію. Майстерня й пазли не отримують окремого набору навчальних правил.

Гід розміщений угорі, під кнопками, окремо від нижньої картки. Портрет збільшено з 96×112 до 164×188 CSS-пікселів. Під час перетягування він залишається в тій самій верхній зоні й показує один поточний відгук. Натискання та утримання відбуваються на полі нижче. Ігрова область враховує верхню зону при початковому кадруванні; текст підказки не пересуває поле під пальцем.

## Усі класи станів

| Стан | Реакція |
|---|---|
| Жодного намету | Коротке пояснення поточної механіки; початок затисканням галявини. На другому рівні не пропонується пересунути ще не встановлений намет. |
| Частина наметів, чинні правила виконані | Прохід вільний; поставити наступний намет. Не вимагати повороту заради уроку. |
| Усі намети й побажання виконані | Запропонувати «Завершити» незалежно від схожості з witness. |
| Чотири повороти | Приймати кожний напрямок, якщо реальні двері доступні. |
| Вихід усередині поля | Перевіряти зв'язність зі входом, а не напрямок відносно камери чи предмета. |
| Вихід поза полем | Дозволяти лише за наявності доступної зовнішньої стежки у правилах версії 2. Самого сусідства із землею недостатньо. |
| Спільні двері та проходи | Дозволяти спільну вільну клітину дверей і спільний маршрут. Пряма лінія чи окремий коридор для кожного не потрібні. |
| Двері зайняті | Назвати намет, двері якого заблоковані, навіть якщо вибрано інший намет. |
| Двері вільні, маршрут відрізаний | Пояснити розірваний маршрут; не стверджувати, що самі двері зайняті. |
| Намет виходить за поле | Пояснити межі; не діагностувати маршрут для некоректної геометрії. |
| Перетин намету, дерева чи каменю | Пояснити перетин. Після переміщення стара площа цього ж намету звільняється за чинною командою сесії. |
| Зайнятий вхід або додаткова точка доступу | Окремо пояснити необхідність залишити вхід вільним. |
| Тінь | Вимога стосується всіх чотирьох клітин намету: 15 неповних масок не підходять, повна маска підходить. |
| Тиша | Усі чотири клітини мають бути поза радіусом шуму: мангеттенська відстань до джерела ≤2 означає шум. |
| Тінь і тиша разом | Після виправлення тіні показати шум, якщо він залишився; не оголошувати місце готовим після виконання лише однієї вимоги. |
| Друг ще не розміщений | Це наступний крок, а не помилка вже встановленого намету. |
| Обидва друзі розміщені | Відстань між дверима по доступних клітинах ≤3 дозволена, >3 — ні. Відстань 0 зі спільними дверима також дозволена. |
| Кілька порушень | Спочатку жорстка заборона, далі проблема вибраного гостя, далі решта; підказка називає постраждалого гостя, для друзів — пару. |
| Поворот, рух, видалення, Undo/Redo, відновлення | Переоцінити актуальну дошку одразу. Старе тимчасове повідомлення не переживає зміну стану чи вибору. |
| Завершення або пропуск навчання | Приховати урок; не повертати стару інструкцію. |
| Невідомий гість або некоректний поворот | Зберегти жорстку помилку канонічного валідатора, не вигадувати проблему дверей. |

## Математична область перевірки

Для намету з кутом `(x,z)` двері задаються чинними правилами: повороти 0, 1, 2, 3 відповідають клітинам `(x+1,z+2)`, `(x+2,z)`, `(x,z−1)`, `(x−1,z+1)`. Маршрут шукається по чотирьох сусідніх клітинах, з урахуванням усіх наметів, блокованих клітин і дозволених зовнішніх стежок.

На першому полі 5×5 є 16 позицій намету 2×2 і 4 повороти. Для двох іменованих гостей перебрано **64² = 4 096** повних розстановок: **660 допустимих**, **116 різних призначень площі двом гостям** без урахування повороту. Допустимі рішення існують для всіх чотирьох напрямків дверей.

Для перших 20 рівнів перебрано **28 944** кандидатні позиції: кожен гість, усі чотири повороти, усі внутрішні кути й одноклітинна смуга за межею. Кожний кандидат перевірено на порожньому полі та серед решти наметів еталонної розстановки. Це повний перебір зазначених двох контекстів, **не** перебір усіх багатонаметових комбінацій на 20 рівнях. Узагальнення на будь-яку розстановку забезпечує виклик тих самих правил під час кожної реальної дії, без списку дозволених місць.

Окремі граничні сценарії охоплюють чотири зовнішні двері зі стежкою і без неї, зайняті й відрізані двері, спільний вихід, усі 16 масок тіні, межу шуму 2/3, межу дружби 3/4, комбіновані побажання та зміну історії сесії.

Перевірка: `learning-tests --profile adaptive`, а також чинні тести навчання й нативні кадри Game View. Локальні докази зберігаються в `QA/UserSettings/AdaptiveTutorial/`. Тести й показаний кадр не є вимірюванням зручності на фізичному телефоні.

2026-10-17: **50/50 цільових EditMode-тестів успішні**, без пропусків: адаптивність 14, сумісність гіда 16, курс 15, вільне розміщення 5. Компіляція пройшла; стилі перевірено через `prepare_ui_styles.py --check`. Відома помилка встановленого Odin 4.0.2.0 залишається окремою залежністю оновлення пакета.

У нативній RAM-сесії перевірено перехід «двері поза стежкою → прохід вільний → наступний намет → усі побажання виконано», утримання з активною сіткою й повернення після скасування. Для uk/en/de переглянуто кадри 750×1334 та 1440×1080, зокрема зі збільшенням тексту до 130%. Верхня картка не перетинається з кнопками шапки та нижньою карткою. Активні файли прогресу обох локальних продуктів після тесту відсутні, резервна копія попередньої сесії збережена.
