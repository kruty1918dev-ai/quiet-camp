# Ігрове промо 100 рівнів

Статус: запис триває. Перші 80 кадрів із UI та сіткою фактично переглянуто; рух у пробному QC001 перевірено окремо. Game View 1440×1080, 30 кадрів/с, 4,33 с, український UI та стереозвук активної гри. Файли містять рух і звичайні дії встановлення/перевірки; це не слайдшоу зі знімків. Фінальний ZIP ще не готовий.

Знімаємо вже прийняті композиції U07 без зміни їхнього оформлення. Повторення запису саме по собі не є новим художнім циклом. Канонічні пазли та попередні ревізії залишаються чинними.

## Відтворення запису

1. Потрібна одна вже відкрита QA-копія Unity. Player builds не запускаються. Пакет [Unity Recorder 5.1.7](https://docs.unity3d.com/Packages/com.unity.recorder@5.1/manual/index.html) записує Game View і фактичний Unity audio mix.
2. `python tools/install_campaign_recorder.py --project <UnityProject>` додає офіційний Recorder. У Unity 6000.6.2f1 / VFX Graph 17.6.0 vendor-файл `VisualEffectActivationTrackMigration.cs` постачається без `.meta`. Після підключення Timeline це спричиняє відсутність `UnityEditor.VFX.Migration`. `--repair-vfx-metadata` відновлює лише відсутню import metadata в локальному PackageCache для перевіреного SHA-256. Vendor C# та встановлення Unity не змінюються. Потім Refresh у чинному Editor. Інші версії не виправляються навмання.
3. `python tools/capture_campaign_promo.py --count 1` — проба; `--count 100` — кампанія. Запис використовує чинний memory-only preview, тимчасовий Pro й внутрішню віртуальну мишу Unity. Фізична миша вимикається тільки в Input System цієї Play-сесії й відновлюється після запису; ОС та інші програми не змінюються.
4. Розміщення проходить через `PlacementController.BeginCardDrag`, його звичайну обробку руху/відпускання й `CampSession`. Завершення — через `qc.check`, перехід — `qc.next`. Еталон задає ціль автоматичного відтворення; у знятому фрагменті `DebugApplyWitness` не використовується.
5. Незавершений запис не приймається. Відновлення пропускає лише фрагменти зі збіжними SHA-256 рівня, композиції, коду запису та обох медіафайлів. Старі успішні рівні можна швидко пройти еталоном поза записом, щоб продовжити з наступного.

Під час першої спроби QC010 зміна фокуса на головне вікно Editor перервала перетягування. Такий фрагмент відхилено й перезнято. `focus_existing_game_view.py` фокусує саме вже відкрите плаваюче Game View **перед** записом, зі звіркою PID; фокус не змінюється посеред перетягування. Інші програми не закриваються.

Оригінали й квитанції: QA `UserSettings/QuietCampPromoCapture/2026-10-15/L001`–`L100`. Звук не підміняється музикою або атмосферою в монтажі: дозволені лише переходи й корекція загального рівня записаного міксу. Для монтажу використовується FFmpeg із Windows-збірки, на яку посилається [офіційна сторінка FFmpeg](https://ffmpeg.org/download.html). Виконувані файли залишаються локальними.

Підсумковий ZIP повинен містити 100 кадрів з UI та сіткою, одне MP4, локальну HTML-галерею, часові позначки, атрибуцію і контрольні суми. Ліміт перевіряється в байтах: менше 100 000 000. Перед видачею потрібні повне декодування відео/аудіо, перевірка кожної картинки й CRC архіву, перевірка звуку та перегляд усіх рівнів і стиків.
