# Перепостановка всіх 100 рівнів

Статус: робота триває; нові композиції ще **не застосовані** до кампанії. Пазли, прогрес, сюжети й унікальні головні моделі зберігаються.

Перший прохід `C01` відрендерено й переглянуто для всіх 100 рівнів у двох ігрових станах. Поле проходить нативні перевірки центра, меж доступної області й оформленого ландшафту. Візуальне приймання **не пройдено**: `C01/inspection.json` містить окремі зауваження до всіх рівнів. Найпомітніші — обрізані споруди, головний об’єкт за UI або поза кадром, майже плоскі силуети наметів при повороті вздовж осі, важкі дерева переднього плану. `C02` уточнює камери перед перестановкою об’єктів. Один незавершений запис рівня 86 відхилено; повторний запис через звичайне розміщення завершився успішно. Жодний невдалий запис не зараховано.

Мета кадру — ігрова площадка з наметами та людьми всередині фактично вільної від UI області. Великий декор не визначає центр і масштаб камери. Для виправлених композицій JSON містить `frameGameplayBoard` і `gameplayCameraMargin`; старі чернетки та історичні ревізії зберігають попередню поведінку. У майстерні є перемикач центрування поля та відступ замість неактивних ручних налаштувань центра.

## Порівняння

`baseline.json` фіксує 100 попередніх ігрових пар у 1440×1080: під час розміщення та після встановлення всіх наметів. Використані перевірені нативні матеріали попереднього промо; контрольні суми рівнів, композицій, PNG та MP4 звірено з обома копіями проєкту. Завершений стан отримано з кадру 118 справжнього запису. Це історична база, а не новий рендер.

Нові кадри знімаються тим самим Game View Recorder у 1440×1080, 30 кадрів/с, через звичайні перетягування та `qc.check`. Для порівняння завершеного стану також використовується кадр 118. Робочі матеріали — QA `UserSettings/QuietCampCompositionReview/B00`, `C01` тощо. Повнорозмірні зображення залишаються локальними; звіти та відтворювані інструменти — у Git.

## Порядок

1. Камера: центр поля, читабельний нахил, розмір, межі оформленої землі, вплив UI.
2. Об’єкти: перекриття поля, цілісні групи споруд і речей, опори, контакт, пропорції. Розміщення через чинний PWB; переміщення головного об’єкта не залишає його залежні речі зависати на старому місці.
3. Освітлення: світло та тіні на таборі зі збереженням сезонної погоди.
4. Рослинність: природні групи в новому кадрі, вільні проходи, єдине покриття поля й оточення.

Кожний рівень проходить щонайменше сім фактичних циклів **перегляд → конкретна правка → нативний кадр → перегляд** за AGENTS.md. Числовий підбір ракурсу лише пропонує варіант. Він не доводить художньої якості й не замінює перегляд. У `corrections.json` та `inspection.json` фіксуються зміни, дефекти, залишкові питання та SHA-256; без нового перегляду цикл не приймається.

Перший пілот рівня 26 з нахилом 62° відхилено: поле правильно потрапило у вільну область UI, але намети стали надто пласкими, а столик опинився за інтерфейсом. Його точні джерела й ігровий запис збережено локально в `Pilot-62`. Наступний підбір обмежено нахилами 48–56°; декор виправляється окремо.

## Спільні системи та перевірки

Кадрування використовує чинні `GameplayViewport`, `GameplayCameraMath` і `CameraFitter`; воно не змінює клітини, колайдери, рішення чи правила перемоги. Розмір ортографічного кадру залежить від пропорцій екрана й доступної області ([Unity: orthographicSize](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/camera/orthographicsize)); фактичне положення перевіряється через [WorldToViewportPoint](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/camera/worldtoviewportpoint).

Editor preview може читати окрему папку композицій без публікації. Початок із довільного рівня готує лише тимчасовий прогрес через чинний `ProgressionService`; усі постійні збереження залишаються ізольованими. Перевіряються кути об’єму наметів і людей, похибка центру, проєкція всього кадру на оформлений ландшафт, стан після розміщення й незмінність прогресу. UI-готовність не означає завершення анімації переходу: запис очікує її стану `Idle`.

Наразі пройшли 13 focused EditMode-тестів, включно з п’ятьма новими випадками кадрування для полів 4–8 клітин, портретного, звичайного й широкого екранів. Це перевірка геометрії кадру, а не приймання всіх 100 композицій. Перед фінальним застосуванням потрібні повний релевантний набір тестів, нативний огляд усіх рівнів і перевірка переходів. Player builds не запускаються.
