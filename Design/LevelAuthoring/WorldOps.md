# QuietCamp WorldOps

WorldOps — одна точка пакетного редагування світу. Майстерня Unity й CLI
`tools/qc_world.py` викликають той самий C# Editor-сервіс. Python передає запити
відкритому Editor і доставляє перевірені файли в Git; він не генерує геометрію
і не змінює документи рівнів.

## Початок роботи

У майстерні розгорніть **WorldOps — пакетні правки**, виберіть JSON-рецепт,
укажіть папку `QuietCamp` у репозиторії та натисніть **Запустити**. Інструмент
використовує поточний Unity; другий Editor і player builds не запускаються.
Звичайна робота в панелі не виконує Git-команд.

```powershell
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp run QuietCamp/Assets/QuietCamp/Authoring/WorldOps/pilot-audit.json
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp status
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp cancel
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp resume --run-id <run-id>
```

Рецепти лежать у `QuietCamp/Assets/QuietCamp/Authoring/WorldOps/`:

| Рецепт | Дія |
|---|---|
| `pilot-audit.json` | QC009, №17, №75: геометрія та Game View, без виправлення й публікації |
| `pilot-contact.json` | Контакт головних об’єктів тих самих рівнів; публікація лише після оцінки |
| `audit-first-ten.json` | Нативна перевірка перших десяти рівнів |
| `audit-all.json` | Технічний аудит усіх 100, без рендерів і художнього приймання |

Журнали, копії, квитанції, кадри та офлайн-звіт `index.html` зберігаються в
`UserSettings/WorldOps/<run-id>/` QA-проєкту. Вони не потрапляють до Resources
чи звичайного Git-коміту. Не виправляйте створені інструментом JSON і хеші вручну.

## Рецепт і спільна реалізація

`WorldRecipe` задає `levelIds` або номери `orders`, seed, операції й критерії.
Порожній вибір означає всю кампанію. Кожна операція має унікальний `id`,
дозволений `kind`, селектор і параметри. Приклад адресної правки:

```json
{
  "version": 1,
  "id": "ground-selected-landmarks",
  "orders": [9, 17, 75],
  "seed": 4157,
  "maxRepairRounds": 5,
  "autoApply": true,
  "operations": [
    {"id": "contact", "kind": "building.ground", "selector": {"primaryOnly": true}, "parameters": {"maximumBurial": 0.04}}
  ],
  "criteria": {"profiles": ["portrait", "landscape"], "quality": 2, "autoRepair": true}
}
```

`autoApply` застосовує готовий результат після поточної художньої оцінки;
він не обходить її. `capture: false` дозволено тільки для аудиту без змін,
автовиправлення та публікації. Статус `audited` не означає `accepted`.

| Група | Дозволені операції |
|---|---|
| Перевірки й камера | `audit`, `camera.frame` |
| Рослинність | `vegetation.redistribute`, `vegetation.scale`, `vegetation.preset` |
| Споруди й ансамблі | `building.move`, `building.ground`, `building.refresh-model` |
| Моделі | `model.age`, `model.simplify` |
| Стежки | `path.upsert`, `path.remove` |
| Оточення | `atmosphere.preset`, `river.edit`, `terrain.stamp` |

Селектор підтримує ID екземплярів і моделей, ролі та `primaryOnly`.
Нерозпізнані ручні об’єкти захищені від загальних операцій; явний вибір
потрібен для їх редагування. `pinned` забороняє переміщення. Метадані `worldOps`
необов’язкові: власник, ансамбль, опора, роль і допустиме заглиблення.
Опори: `grounded`, `water`, `object:<stable-id>`. Старі чернетки відкриваються
без масового перезапису. Обростання переноситься разом із власником і не
розсіюється звичайним перерозподілом трави.

Операції делегують чинним PWB, інструментам моделей, старінню, пресетам,
MicroVerse/River Modeler. Зміни річки й stamps очікують справжнє запікання Terrain.
Геометрію стежок створює спільна операція з мітровими стиками. Витоптування
ігрової зони залишається відповідальністю наявної системи використання ґрунту.
Нова можливість додається до C# allow-list разом із перевірками, а потім
використовується через цей процес. Старі Python-публікатори є обгортками CLI.

## Перевірка та рецензування

Послідовність: знімок джерел → підготовка → об’єктивні перевірки → дозволені
виправлення → Game View → висновок агента → транзакційне застосування.
Максимум п’ять раундів; дві спроби без поліпшення переводять дефект у винятки.

Перевіряються чинні пазли й еталонні рішення, резервування унікальних головних
моделей, контакт трансформованої геометрії з опорою, рослини у воді та спорудах,
захищені проходи, кінці й нахил стежок, масштаб клітин, центр поля, межі землі,
обрізання та перекриття головного об’єкта. Свідоме заглиблення задається явно.

Нативний прогін використовує справжні сцени, UI та команди розміщення наметів.
Профілі — **750×1334** і **1440×1080**, стани — порожнє поле, розміщення й
установлені намети. Для зміненого документа знімаються до/після; незмінний аудит
не дублює однакові кадри. Тестове збереження працює тільки в пам’яті.
Для атмосферних правок запускається також запис руху й перевірка рівневого звуку.
Якість, seed та час захоплення фіксуються.

`*.id-depth.png` і `*.isolated.png` — діагностика, не ігрові рендери. Маска
враховує фактичну сезонну геометрію головного об’єкта та його runtime-трансформу;
прозорий туман і сітка не вважаються непрозорою перешкодою. Вітер у матеріалах
рослин не відтворюється діагностичним шейдером побітово: спірні краї перевіряє
агент за справжнім кадром. Поріг видимої площі — 75% проєкції силуету.

Агент переглядає всі актуальні кадри й передає окремий `ReviewVerdict` командою:

```powershell
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp review <verdict.json>
```

Висновок містить `runId`, `levelId`, `round`, `inputHash`, `documentHash`,
`reviewer`, `accepted`, `inspectedFrameHashes`, `corrections`, `residuals`, `notes`.
Хеші мають відповідати всім кадрам поточного `ReviewPacket`. Структурований
висновок агента — авторський документ, а не редагування згенерованої квитанції.
Невирішені помилки, змінені кадри, джерела чи квитанції блокують приймання.
Без агента результат очікує оцінки. Початковий аудит не приймає дефекти за еталон.

## Кеш, синхронізація та застосування

Ключ кешу враховує документ, рецепт, імпортовані залежності, матеріали, шейдери,
збірки, Unity, пакети, цільову платформу й налаштування якості. Використовується
[AssetDatabase.GetAssetDependencyHash](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AssetDatabase.GetAssetDependencyHash.html).
Читання масок використовує [AsyncGPUReadback](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.AsyncGPUReadback.html)
з очікуванням завершення та CPU-резервом. Повторно використовуються лише докази,
файли яких залишилися незмінними; старий художній висновок не підміняє новий.
Архівні roadmap-шейдери та шейдер мініатюр каталогу не впливають на захоплення.
Інші QA-локальні legacy-файли обліковуються як залежності; спільні джерела мають
збігатися з репозиторієм.

Зміни зі збереженим ID оновлюють сцену та наступне збереження. Нові ручні/PWB
об’єкти, ще не записані в документ, зберігаються; явне видалення відомого об’єкта
виконується. Локальна правка рослини не перебудовує всю рослинність.

Запис використовує спільний `LevelAuthoringCampaign.PrepareApply`, історію
контенту, перевірку вихідних хешів і журнал із резервними копіями. Пазли обох
коренів перевіряються один раз на актуальний стан, а не перед кожним записом.
Готові незалежні рівні застосовуються окремо. Моделі рецептів зберігаються всередині
документа; спільні вихідні бібліотеки рецепти не перезаписують.

Репозиторій, QA, історія й чернетка входять до однієї транзакції. Чиста відкрита
чернетка оновлюється; незбережені зміни відповідного рівня блокують запис і відкат.
Відкат також перевіряє всі цільові файли перед першим записом і зберігає пізнішу
роботу користувача. Перерваний запис можна продовжити через журнал.

```powershell
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp apply
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp rollback <level-id>
```

Для явно ввімкненої агентної доставки використовуйте `run ... --agent-delivery`,
після приймання — `deliver --push`. Інструмент перевіряє квитанції та журнал,
виключає групи з попередніми користувацькими змінами й комітить лише власні файли.
Сторонні staged-файли зберігаються. `verify-publication` вимагає всіх 100
актуально прийнятих і застосованих рівнів; технічного аудиту для цього недостатньо.

## Перевірений стан реалізації — 2026-10-16

21 фокусний нативний тест пройшов: синхронізація ID/геометрії, ручні деталі й PWB,
опори, групи, стежки, рослини у воді, захист ручного обростання, пошкоджені докази,
переривання транзакції та захищений відкат. Три ізольовані Python-тести доставки
пройшли. У попередньому повному запуску було 212 успішних і один невдалий тест;
знайдену регресію збереження ручних об’єктів виправлено, її окремий Terrain-тест
тепер проходить. Це не підміняє фінального повного повторного запуску.

зайняв 117,66 мс без повної перебудови. Це час операції Editor, а не мобільний FPS.
