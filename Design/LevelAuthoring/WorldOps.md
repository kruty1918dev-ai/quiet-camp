# QuietCamp WorldOps

V03 має окремі вступні проби й монтаж: `teaser ... --version v03-a|v03-b|v03-c|v03-rough|v03`.
Почніть із [етапів виробництва та повторного запису](../../QuietCamp/Assets/Marketing/TeaserV03/REPRODUCTION_GUIDE.md).
Режим `v03` називає результат **Review**, доки агент не підтвердив усі художні критерії.
Технічні перевірки не присвоюють статус Final. V01/V02 збережені окремо.

Для ізольованого ігрового тизера використовуйте те саме ядро через
`qc_world.py ... teaser create|validate|reframe|preview|record|status`.
Для V02 додавайте `--version v02`: окремі 13 планів, журнал, assets та export.
[V02: повторний запис, монтаж і QA](../Marketing/Teaser/V02/README-UA.md).
Без цього параметра CLI зберігає режим V01; пакетуванню й review теж передається
`--version v02`. Художні докази однієї версії не переносяться на іншу.
Розширення знімає чинні рівні без переписування кампанії, приховуючи UI лише
за окремим маркетинговим завданням. Під час нього інші native mutations блокуються.
[Інструкція, монтаж і фактичне QA 42-секундного тизера](../Marketing/Teaser/README-UA.md).
Технічний запис не означає художнього приймання; verdict прив'язується до
актуального MP4 та декодованих кадрів. Це не заміна звичайних WorldOps перевірок із HUD.

Для зимового покриття використовуйте `snow-volume-balanced.json` (якість 1)
або `snow-volume-pilot.json` (якість 2). Опис спільної геометрії снігу,
матеріалу та перевірки завірюхи: [SnowGround-UA.md](SnowGround-UA.md).

Перемикання нативного прев’ю використовує атомарний запис WorldOps. Якщо Windows
тимчасово блокує службовий JSON, дозволено до трьох повторів через 0,5 с без
блокування Editor. Стан переходить у `starting` лише після успішного запису;
невдалий запуск залишається у `launch` й може бути відновлений через `resume`.

WorldOps — одна точка пакетного редагування світу. Майстерня Unity й CLI
`tools/qc_world.py` викликають той самий C# Editor-сервіс. Python передає запити
відкритому Editor, показує прогрес і доставляє перевірені файли в Git.
Він не генерує геометрію та не змінює документи рівнів.

## Рецепт і спільна реалізація

`WorldRecipe` задає `levelIds` або номери `orders`, seed, операції й критерії.
Порожній вибір означає всю кампанію. Кожна операція має унікальний `id`,
дозволений `kind`, селектор і параметри. Приклад адресної правки:

```json
{
  "version": 1,
  "id": "ground-selected-landmarks",
  "orders": [9, 17, 75],
  "seed": 4157,
  "maxRepairRounds": 5,
  "autoApply": true,
  "operations": [
    {"id": "contact", "kind": "building.ground", "selector": {"primaryOnly": true}, "parameters": {"maximumBurial": 0.04}}
  ],
  "criteria": {"profiles": ["portrait", "landscape"], "quality": 2, "autoRepair": true}
}
```

`autoApply` застосовує готовий результат після актуальної художньої оцінки;
він не обходить її. `capture: false` дозволено тільки для аудиту без змін,
автовиправлення та публікації. Статус `audited` не означає `accepted`.

| Група | Дозволені операції |
|---|---|
| Перевірки й камера | `audit`, `camera.frame` |
| Рослинність | `vegetation.refine`, `vegetation.redistribute`, `vegetation.scale`, `vegetation.preset` |
| Споруди й ансамблі | `building.move`, `building.ground`, `building.refresh-model` |
| Моделі | `model.age`, `model.simplify` |
| Стежки | `path.upsert`, `path.remove` |
| Оточення | `atmosphere.preset`, `river.edit`, `terrain.stamp` |
| Ґрунт і луг | `ground.refine`, `vegetation.refine` з `continuousMeadow`, `flowerCoverage`, `accentRetention` |

`ground-pilot.json`, `meadow-pilot.json`, `meadow-flowerfield.json` — окремі
попередні перегляди землі й рослинного покриву. Правила спільної реалізації:
[Природний ґрунт і суцільний луг](NaturalMeadow-UA.md).

Для покриву всієї мапи є `meadow-map-coverage.json`.
`criteria.inspectMapCoverage: true` додає чотири дальні ділянки ландшафту
в кожному профілі. Знімки `environment-coverage-*` мають тимчасово зміщену
камеру та є діагностикою оточення. Вони входять до хешованого пакета оцінки,
але не замінюють звичайні ігрові кадри. JSON біля кожного знімка містить
межі покриву, точку огляду й кількість ділянок геометрії. Використовувати
цей режим для зелені, щоб гарний центр не приховував порожні дальні зони.

`criteria.includeMenu: true` додає головне меню в кожному профілі навіть
для аудиту спільного рендерера без зміни JSON рівня. Це ввімкнено в
`meadow-map-coverage.json`: зміна матеріалів або пом’якшення зелені повинна
переглядатися також у фоні меню. Кадри меню входять до того самого пакета
оцінки та перевірки хешів.

`previewOnly: true` дозволяє отримати кадри вибраних рівнів, коли загальна
перевірка кампанії заблокована іншим пазлом. Вибрані пазли й їхні рішення
все одно перевіряються; знімок джерел, геометрія та оцінка кадрів зберігаються.
Цей режим вимагає `capture: true`, `autoApply: false` і ніколи не дозволяє
публікацію, навіть після позитивної оцінки кадрів. Для застосування потрібен
звичайний запуск з успішною повною перевіркою кампанії. Квитанція позначає
область як `selected-preview-only`, а не як прийняту кампанію.

Селектор підтримує ID екземплярів і моделей, ролі та `primaryOnly`.
Нерозпізнані ручні об’єкти захищені від загальних операцій; потрібен явний
вибір для їх редагування. `pinned` забороняє переміщення. Необов’язкові
метадані `worldOps` задають власника, ансамбль, опору, роль і заглиблення.
Опори: `grounded`, `water`, `object:<stable-id>`. Старі чернетки відкриваються
без масового перезапису. Обростання переноситься разом із власником і не
розсіюється звичайним перерозподілом трави.

Операції делегують чинним PWB, інструментам моделей, старінню, пресетам,
MicroVerse/River Modeler. Річка й stamps очікують справжнє запікання Terrain.
Стежки мають редаговані точки й спільні стики. Витоптування ігрового поля
залишається відповідальністю наявної системи використання ґрунту.
Нову можливість додають до C# allow-list разом із перевірками, потім
використовують через цей процес. Старі Python-публікатори є обгортками CLI.

## Перевірка та рецензування

Послідовність: знімок джерел → підготовка → об’єктивні перевірки → дозволені
виправлення → Game View → висновок агента → транзакційне застосування.
Максимум п’ять раундів; дві спроби без поліпшення того самого дефекту
переводять рівень у винятки. Факт зміни JSON не є поліпшенням.

Перевіряються пазли й еталонні рішення, унікальні головні моделі, контакт
трансформованої геометрії з опорою, рослини у воді та спорудах, проходи,
кінці й нахил стежок, масштаб клітин, центр поля, межі землі, обрізання
та перекриття головного об’єкта. Свідоме заглиблення задається явно.

Нативний прогін використовує справжні сцени, UI й команди розміщення наметів.
Кожен gameplay-стан також має `*.geometry-census.json`: кількість індексованих трикутників усіх завантажених примірників MeshRenderer/SkinnedMeshRenderer, зокрема неактивних; окремо — активні, унікальні меші, кандидати у frustum, джерела тіней і UI. Повторні shadow/depth/color passes не додаються до геометрії сцени. Частинки, trails і terrain перелічені як непораховані динамічні renderer-и: mesh total є нижньою межею, а не доказом повного бюджету. Цей read-only census не змінює картинку й сам собою не забезпечує 50 000; він показує фактичний розрив і найбільші джерела геометрії.
Профілі: **750×1334** і **1440×1080**; стани: порожнє поле, розміщення,
установлені намети. Для змін знімаються до/після й головне меню; незмінний
аудит не дублює однакові кадри. Прогрес зберігається тільки в пам’яті.
Погодні правки включають нативний відеозапис зі звуковим міксом гри.
Якість, seed і час захоплення фіксуються; налаштування відновлюються після виходу.

`*.id-depth.png` і `*.isolated.png` — діагностика, не ігрові рендери. Маска
враховує фактичну сезонну геометрію та runtime-трансформу головного об’єкта.
Прозорий туман і сітка не вважаються непрозорою перешкодою. Порівняння
16-бітної глибини має допуск 15,6 мм для CPU/GPU-трансформацій. GPU-тест
перевіряє самоперекриття, справжню перешкоду й орієнтацію кадру. Поріг
видимої площі — 75%. Вітер у матеріалах рослин не відтворюється маскою
побітово: спірні краї оцінює агент за справжнім кадром.

[SetViewProjectionMatrices](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityengine/rendering/commandbuffer/setviewprojectionmatrices)
не використовується як залежність від глобального стану камери URP.

Агент переглядає актуальні кадри й передає авторський `ReviewVerdict`:

```powershell
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp review <verdict.json>
```

Висновок містить `runId`, `levelId`, `round`, `inputHash`, `documentHash`,
`reviewer`, `accepted`, `inspectedFrameHashes`, `corrections`, `residuals`, `notes`.
Хеші відповідають усім кадрам поточного `ReviewPacket`. Структурований
висновок — авторський документ, а не редагування згенерованої квитанції.
Невирішені помилки, змінені кадри, джерела чи квитанції блокують приймання.
Без агента результат очікує оцінки. Аудит не приймає дефекти за еталон.

## Кеш, синхронізація та застосування

Ключ кешу включає документ, рецепт, імпортовані залежності, матеріали,
шейдери, збірки, Unity, пакети, платформу й якість. Використовується
[GetAssetDependencyHash](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AssetDatabase.GetAssetDependencyHash.html).
Маніфест враховує текстури, аудіо й спільні бібліотеки моделей, фізичні
джерела та .meta QA. Зовнішня зміна джерела інвалідує докази ще до імпорту.
Робочі сцени, палітра та окремі документи/ревізії мають явні винятки.
Захищені відмінності QA, зокрема renderer-асети, не перезаписуються.

Маски читаються через [AsyncGPUReadback](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.AsyncGPUReadback.html)
з очікуванням завершення та CPU-резервом. Незмінні кадри «до» повторно
використовуються після перевірки SHA-256 і квитанцій. Старий художній
висновок не підміняє новий. Невдала компіляція блокує запуск і застосування.

Зміни зі збереженим ID оновлюють сцену та наступне збереження. Нові ручні/PWB
об’єкти, ще не записані в документ, зберігаються; явне видалення відомого
об’єкта виконується. Локальна правка й зовнішнє застосування до чистого
відкритого вікна не перебудовують усі 10 000 рослин. Незавершена робота
з копією моделі або її попереднім переглядом створює конфлікт.

Запис використовує `LevelAuthoringCampaign.PrepareApply`, історію контенту,
перевірку вихідних хешів і журнал із резервними копіями. Пазли обох коренів
перевіряються один раз на актуальний стан. Готові незалежні рівні застосовуються
окремо. Моделі рецептів зберігаються всередині документа; спільні вихідні
бібліотеки рецепти не перезаписують.

Репозиторій, QA, історія й чернетка входять до однієї транзакції. Чиста
відкрита чернетка оновлюється; незбережені зміни рівня блокують запис і відкат.
Відкат перевіряє всі цільові файли перед першим записом та зберігає пізнішу
роботу користувача. Перерваний запис можна продовжити через журнал.

```powershell
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp apply
python tools/qc_world.py --project C:/Users/Public/qcui-20261006/QuietCamp rollback <level-id>
```

Явно ввімкнена агентна доставка: `run ... --agent-delivery`, після приймання —
`deliver --push`. Перевіряються квитанції й журнал, виключаються групи з
попередніми змінами користувача, комітяться лише власні файли. Сторонній
Git index зберігається. `verify-publication` вимагає всіх 100 актуально
прийнятих і застосованих рівнів; самого аудиту недостатньо.

## Природний масштаб зелені

`greenery-pilot.json` перевіряє №9, №17 і №75; `greenery-all.json` обирає
всі 100 рівнів. Обидва викликають `vegetation.refine` у спільному C#-сервісі.
Операція працює з наявними окремими об’єктами та налаштовує чинне сіткове
покриття поля в `CampGroundDetails`. Нового шару рослинності не створює.

- Розмір визначається трансформованими вершинами, включно з нахилом і
  неоднаковим масштабом по осях. Надмірні рослини зменшуються пропорційно:
  у рецептах v2 трава обмежена 0,48 м заввишки і 0,85 м завширшки;
  квіти зберігають вищий силует. Перші вужчі межі переглянуто за Game View.
  Детермінована варіація 80–100% цих меж зберігає різні розміри сусідніх
  рослин; повторний запуск не зменшує їх знову.
- На полі залишається низьке природне покриття до 0,14 м заввишки, без
  оголених місць під майбутні намети. Маленькі рослини не збільшуються.
- Дерева зберігають розмір. Справжні нижні вершини рослин контактують із
  ґрунтом. Помилкові корені у воді, спорудах або захищених проходах отримують
  детермінований пошук нового місця поряд. Невиправлений дефект лишається
  у звіті й блокує приймання.
- Закріплені об’єкти, водні рослини з роллю `aquatic`, обростання `overgrowth/`
  і рослини з опорою `object:<id>` зберігаються. Масовий рецепт явно дозволяє
  роботу з ручною зеленню через `generatedOnly: false`; це не дозвіл змінювати
  будівлі або головні об’єкти.
- Сезонна геометрія, вітер, вологість та приминання використовують чинні
  системи. Новий шар runtime-рослинності не створюється.

`parameters.fieldCover` записує необов’язковий `art.fieldCover`: густота
спроб на квадратний метр, максимальні висота й ширина, ширина переходу
за поле та частка широколистих моделей. У v2 це 7 / 0,14 м / 0,28 м /
3 м / 20%. Покриття плавно рідшає за краєм поля, пропускає воду та зайняті
клітини й використовує ті самі вітер і приминання. Без цих даних старі JSON
працюють за попереднім алгоритмом; міграція не потрібна. Майстерня оновлює
лише поле, коли цей профіль змінився, і не перебудовує всю зелень.

`camera.frame` має межі 1,02–1,6 і зберігає центр земної ігрової площини
в центрі доступного viewport. Канонічний повторний підбір камери тепер
використовує заданий margin замість перезапису його типовим масштабом.
Звичайна камера без authored-прапорця зберігає попередню поведінку.
Широкий dock резервує місце для завершення; повідомлення переходить
на окремий рядок. CSS редагується в `Camp.css.txt`, похідні стилі
отримуються через `tools/prepare_ui_styles.py` і перевіряються `--check`.

Пакетна зміна масштабу або вертикального контакту вже наявних ID не створює
їх повторно через PWB. Нові об’єкти, зміна горизонтального положення або
обертання й надалі проходять через адаптер розміщення. Для обох шляхів
обов’язкові геометричні перевірки й Game View; `placement-receipt.json`
показує справжню кількість повторних розміщень. Це усуває зайву роботу з
тисячами рослин, не даючи технічному результату художнього приймання.

Класифікація враховує явний `seasonalRole`, а не лише шейдер: тканина
`motion: cloth` і деталі `solid` не є зеленню навіть із foliage-шейдером.
Для білизни на мотузці перевіряється справжній шарнір чинного
`WeatherModelRigAuthoring`: точка підвісу мусить лежати всередині геометрії
мотузки власника. Втрата контакту створює `support.missing`. Шість початкових
`vegetation.floating` на №42–44 були такою помилкою класифікації, а не
рослинами, які потрібно опустити на землю. Виправлення зберігає їхній рух.

Після цих змін: 42 focused EditMode тести пройшли, включно з підвісом,
масовим масштабуванням 10 000 рослин та захистом старих точок входу;
сім тестів Python перевіряють доставку, маршрутизацію обгорток і повторне
читання тимчасово заблокованої відповіді Editor. Окремі 13 перевірок вступної
кампанії підтвердили центр земної площини та потрапляння дахів у viewport
для п’яти різних пропорцій кадру й кутів.

Для агентів правила розміщені також у `tools/AGENTS.md` і
`Assets/QuietCamp/Authoring/AGENTS.md`. Editor перевіряє старі native-запити:
пакетні `forest-regrowth`, `opening-details`, `opening-compose`,
`opening-apply`, `object-overgrowth`, `crash-compose`, `season-variant`,
`campaign-regenerate`, `campaign-weather-upgrade` відхиляються з посиланням
на WorldOps. Тести, читання стану та звичайне ручне редагування не блокуються.
Це контроль відомих точок входу, а не твердження про нагляд за сторонніми
процесами чи довільними файловими командами.

Старі `render_story_campaign.py` та `run_story_campaign_batch.py` також
делегують WorldOps. Без рецепта вони виконують лише Game View аудит вибраного
діапазону; `--compose` вимагає явного `--recipe`. Прямого запису трансформів
або повторного запуску старого генератора в цих обгортках більше немає.

Для автоматичного вибору процесу Codex встановлено навичку
`quietcamp-worldops` з `allow_implicit_invocation: true`. Вона впізнає запити
про QuietCamp, навіть коли чат відкритий у Moyva, і спрямовує до цього сервісу.
Джерело: `tools/agent-skills/quietcamp-worldops/`. Локальна встановлена копія:
`~/.codex/skills/quietcamp-worldops/`; `~/.agents/skills/quietcamp-worldops/`
посилається на ту саму папку для сучасного шляху виявлення навичок.
Початкові файли й YAML перевірено валідатором skill-creator. Навичка вже
з’явилася в актуальному каталозі навичок цієї сесії, отже встановлення
виявляється системою. Неявний вибір окремим агентом ще не перевірявся;
активних підлеглих агентів у цій сесії немає. Відомі старі native-команди блокуються
незалежно від вибору навички.

## Експеримент бюджету геометрії

Для аудиту фактичного runtime-оформлення є `runtimePresentation: true`
у рецепті `grass-density-review.json`. Сервіс створює presentation-копію
через ту саму політику `CampGeometryBudget`, що й звичайне завантаження гри.
Потрібні `previewOnly: true`, `autoApply: false`, тільки операції `audit`
і повний `maximumSceneTriangles: 50000`. Публікацію та мутації заборонено.
Канонічні документи й хеші джерел зберігаються; геометрія та Game View
перевіряються для реально використовуваного покриву. Без цього прапорця
зберігається звичайний authored до/після процес.

`vegetation.heightfield-preview` дозволено лише з `previewOnly: true`.
Він читає геометрію з канонічного `CampGroundDetails`, замінює тільки траву
й залишає квіти з точними вихідними координатами, нормалями, лінійними
кольорами та вагами вітру. Карти й квіткові канали зберігаються у staged-документі,
а не в опублікованій кампанії. Дані експерименту, renderer і його shader
виключені з player. Звичайний запуск гри використовує початкову геометрію.

`resolution` задає 256, 512 або 1024; `adaptive: true` подвоює деталізацію
біля поля (максимум 1024), залишає задану на середній відстані й зменшує
вчетверо за 22 м. Це пілотна евристика, а не доведена відповідність усім
ракурсам альбому чи розмірам екрана. Трасування висоти спільне для кольору,
глибини й маски рослинності; освітлення та погода використовують спільні
`CampArtSurface.hlsl` і `CampArtWeather.hlsl`. Безперервний луг у джерелі
не відкидає тіней; приймання тіней зберігається. Варіанти shader з різними
режимами тіней компілюються синхронно до початку bake.

Цей пілот ще не забезпечує 50 000 трикутників усієї сцени. Один верхній
шар висоти може втрачати перекриті поверхні; кількість трикутників сама
не доводить незмінність зображення або прискорення GPU. Порівнюйте фактичні
кадри обох орієнтацій, фази вітру, глибину, освітлення, витрати пам’яті
й час GPU перед будь-яким подальшим застосуванням.

Для пасивного вимірювання можна скопіювати `tools/qa/WorldOpsPerformanceProbe.cs`
в Editor-папку чинної QA-сесії. Він спостерігає лише за кадрами WorldOps
і записує `editor-performance.json` поруч із ними; не запускає Unity,
Play Mode, player build та не змінює налаштувань. Порівнюйте однакові
формати до/після, відкидаючи прогрів. Ці вибірки включають UI й окремі
діагностичні рендери та не є вимірюванням FPS на Android.

Поточний варіант відхилено: після збереження квітів QC007 має 610 469
меш-трикутників у порожньому стані, а медіана GPU в Editor зросла
з 20,70 до 60,07 мс у портреті та з 25,09 до 86,83 мс в альбомному форматі.
Він залишається дослідним інструментом і не виконує ціль 50 000.

## Перевірка без Unity — 2026-10-21

`external-audit` — окремий read-only backend тієї самої CLI. Потрібні безплатні
.NET 10 та Blender 4.3+, ліцензія Unity не потрібна. Він читає 100 активних
рівнів, фактичні запечені меші, сезонну геометрію чинного C# коду та оригінальні
OBJ ігрових об’єктів. Архівні 274 ревізії не додаються до кампанії.

```bash
python3 tools/qc_world.py --project QuietCamp external-audit \
  --output /absolute/path/outside-Assets/audit --render
```

`--orders 3 36 100` обмежує вибір; `--resource-root` дозволяє read-only корпус
ресурсів, чиї tree/hash збіги з main перевірено окремо. `--dotnet` і `--blender`
задають executable. `--skip-export` повторює рендер уже підготовлених bundles.
Рендер можна продовжити: backend перевіряє хеші input/renderer/наявних кадрів.

Blender Workbench відтворює геометрію, а не Unity URP. HUD не запускається:
напрямок та межі камери взяті з коду, резерв UI є оголошеним припущенням.
Окремі coverage/detail кадри мають інше збільшення і позначені діагностикою.
Шейдери SW3, перебудова річки, процедурний луг, частинки, рух тканини й предмети
мешканців не оголошуються відтвореними. Чорні службові RGBA води не є її кольором;
для зовнішнього перегляду використано shallow tint справжнього матеріалу.

`--composition-candidates` викликає **ті самі C# WorldOps operations**, складає
пропозиції поза Assets і записує відмови. Це не apply, не native capture і не
художнє приймання. Операції: `well.opening`, `bridge.crossing`, `shade.support`.
Криниці отримують виріз землі за реальним внутрішнім контуром та темну шахту;
мости перетинають фактичну вісь русла, мають сухі кінці, опори й короткі підходи.
Навіс не змінює сонце/пазл/камеру; відмовляє при перетині поля, споруд,
непридатному березі, надмірній висоті чи виході за ландшафт. Позитивні числові
перевірки не доводять гарного силуету: потрібен огляд перекриттів головного
об’єкта та наметів. Рецепти `composition-contact-pilot.json` і
`shade-support-pilot.json` залишають `autoApply:false` та чинний review gate.

Runtime усуває повторне перекриття справжніх шахт перебудованою річкою,
процедурними рослинами/камінцями й зимовим снігом; це presentation bug fix без
переписування авторських JSON, пазлів або збережень. Нативні тести
`CompositionContactTests` підготовлено; portable checks не видаються за їх запуск.

Підсумок зовнішнього огляду: [100 окремих висновків](CompositionAudit/2026-10-21/REPORT.md).
Шість шахт належать 003/009/063/078/100 (на 100 дві). У 036/038/057/088
операція мостів зберігає унікальний головний міст і прибирає накладений старий
дублікат; у 069 повертає єдиний старий міст упоперек русла. Довгі стежки та
нативний контакт берега ще не прийняті. Жоден із 12 дослідних навісів не є
готовим оформленням; числова тінь не виправдовує перекриття криниці чи повтор
однакового силуету. Workbench не відтворює зимовий сніговий матеріал 071–088.

Після експорту й завершеного рендеру додаткові read-only звіти готуються так:

```sh
python tools/world-audit/analyze.py /path/to/audit
python tools/world-audit/contact_inventory.py /path/to/audit
python tools/world-audit/contact_sheets.py /path/to/audit
# Після фактичного огляду кадрів і запису review-notes.json:
python tools/world-audit/build_report.py /path/to/audit
```

Ці Python-звіти потребують Pillow та NumPy. Ручні нотатки — діагностичні,
не WorldOps ReviewVerdict. Повний звіт не створюється без усіх 100 нотаток.
