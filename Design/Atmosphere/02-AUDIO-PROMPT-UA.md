# Промпт для ШІ: звуковий світ QuietCamp — простір, тиша й затишок

Ти — агент, який реалізує аудіооформлення QuietCamp у Unity 6. Прочитай цей документ цілком, звір поточні файли проєкту й реалізуй вимоги. Це самодостатній промпт: факти аналізу, мапа звуків, параметри, порядок робіт і критерії приймання наведені тут. Не створюй другу аудіосистему поряд із наявною.

## 1. Художній результат

Гравець відчуває маленьку захищену галявину всередині живого лісу. Поруч — тихий дотик тканини й дерева, у середньому плані — вогонь, далеко — птах чи сова. Вітер пов’язує рух рослин, листя й звук. Між виразними подіями є тиша.

Пріоритети: зрозумілий відгук на дію → комфорт → причинність → просторова глибина → декоративні деталі. Тихий мікс не означає нечутного підтвердження. Простір не означає ехо на кожній кнопці. Кожен виразний звук має джерело, причину, власника і момент завершення.

Не додавати випадкові кроки, шепіт, моторошні гуки, різкі сигнали, постійні дзвіночки чи музику лише для заповнення пауз. Не озвучувати кожну травинку й частинку. Вогонь не повинен тріщати окремим one-shot на кожну іскру.

### Висновки й корекція до мікшування

1. **Wind/fire:** різниця RMS 31.16 dB. За Volume 0.20/0.18 та дистанційного ослаблення fire вітер може його маскувати. Спершу зменшити wind і прослухати активні фрагменти вогню. Не підсилювати fire автоматично на 31 dB: RMS із паузами не описує піки потріскування.
2. **Crickets:** нині peak −5.20 dBFS, немає семплів з |x|≥0.999. Попередні піки біля 0 dBFS вже виправлені. Endpoint delta 0.029633; RMS перших 20 мс −16.39, останніх −42.93 dBFS. Перевірити стрибок енергії й клацання на десяти повторах.
3. **Twig:** peak −1.38 dBFS, також немає семплів |x|≥0.999. Endpoint delta 0.835785 — для одноразового удару це не дефект петлі. Перевірити комфорт різкого старту, не стерти характер звуку.
4. **Wind DC:** середній зсув PCM близько −0.017. Порівняти похідну з корекцією DC/дуже низьких частот; не вмикати через це фільтр на всіх джерелах.
5. **Хвости:** endpoint delta rustle 0.014954, chime 0.018982, fire 0.010529, wind 0.000183. Прослухати після імпорту; малий delta не гарантує непомітного спектрального переходу.
6. **Процедурні тембри:** перевірити, чи crickets не нагадують електронний писк, owl — синтезатор, gust — різкий шум. Назва файлу не підтверджує художньої придатності.

Працювати з похідними файлами або відтворювано коригувати генератор власних записів, зберігаючи оригінали й .meta. Для crickets почати з overlap 80–160 мс та правильного циклічного wrap; не робити провал у тишу кожні 8 с. Для корельованого матеріалу equal-power crossfade може підвищувати рівень — перевірити linear. Короткі fade 1–5 мс на one-shot додавати лише там, де є підтверджений обрив/клацання.

## 5. Просторовий звук і listener

Використати чинний ListenerProxy. Рівно один активний AudioListener у MainMenu, Camp і при переходах. Перевірити прямий запуск сцени та меню → гра → меню.

Розмістити proxy над фактичним центром поля, початково на висоті 1.6–2 розміри клітинки. (0,0,0) допустимий тільки для справді центрованого поля. Орієнтація узгоджена з камерою: джерело ліворуч на екрані чути ліворуч. Зміна orthographic size сама не змінює відстань до listener.

Косметичний plunge камери не переносить listener крізь джерела. Використати окремий rustle й керовані ваги. Doppler = 0 для цього набору. Звичайний 3D AudioSource не означає автоматичний HRTF; сторонній spatializer не є вимогою.

Познач c = розмір клітинки у world units. Стартові дистанції:

| Джерело | Min / Max | Поведінка |
|---|---|---|
| Fire | 2c / 14c | Чутний поруч, слабшає вдалині |
| Bird | 4c / 24c | Крона середнього/далекого плану |
| Owl | 3c / 30c | Край лісу, не центр екрана |
| Gust | 4c / 26c | Порив із боку входу в галявину |
| Локальний rustle | 1.5c / 8c | Ближня деталь; поточні 2/18 переглянути |
| Placement | 2c / 12c | Відгук чутний по всьому робочому полю |

Значення уточнити на найменшому/найбільшому полі. Не вважати MaxDistance гарантованим нулем у logarithmic rolloff. Для передбачуваного нуля взяти linear або підтриману custom curve. Старт custom curve за нормованою відстанню: 0→1, 0.25→0.8, 0.6→0.3, 1→0; перевірити одиниці API та згладити. Не ставити anchor за межі радіуса чутності.

Для точкових fire/bird/placement за потреби створити mono-похідні, перевіривши фазову сумісність stereo→mono. Wind залишити stereo.

Особливість чинного сервісу: Play із Position, включно з PlayAt, примусово піднімає spatialBlend до 1; scene override може змінити його пізніше. Не очікувати blend 0.4 лише від каталогу при PlayAt. Transition-rustle використовує Play без Position із 2D-конфігурацією. Для проміжного blend потрібен явний підтриманий контракт, а не приховані щокадрові записи в AudioSource.

## 6. Ехо, реверберація й приглушення

Ехо — окремі повтори, reverb — розсіяне післязвуччя. Галявина не повинна звучати як печера. Спочатку збалансувати сухий мікс.

### Сова й далечінь

Наявні 180 мс / decay 0.25 / wet 0.12 / dry 1 — старт. Робочий діапазон: delay 160–230 мс, decay 0.18–0.25, wet 0.06–0.12. Один слабкий відбиток достатній. Delay не змінювати під час фрази. Bird за замовчуванням без echo. UI, placement, twig, ближній rustle, wind-bed і cricket-bed сухі.

Для Balanced/High допустимий один shared reverb-return вибраних далеких джерел: художній орієнтир decay 0.35–0.65 с, темний хвіст і мінімальний send. Це пропозиція, не наявні параметри AudioEffectSettings. Поточний контракт reverb задає лише preset: не вигадувати DecayTime/Send API. Використати QC_Master або вузько розширити чинний контракт. Не ставити Room/Cave на всі sources. Якщо слухова користь мала — залишити глибину через 3D, рівень і echo сови. Low без live reverb.

Не накладати одночасно source reverb, zone та mixer reverb без окремої причини.

### Перешкоди й листя

Для реально закритого кущем джерела допустимий плавний low-pass 16–20 kHz → 6–9 kHz і gain −2…−4 dB за 150–300 мс, без резонансного піку. Звичайна трава не стіна; перекриття спрайтів не є акустичною перешкодою.

Спочатку семантичний стан/відомий anchor. Якщо потрібна physics occlusion: максимум 2 активні близькі джерела, по одному raycast до 5 Гц, виділений layer mask. Не raycast на кожне дерево щокадру.

### Хвіст і пул

Сервіс зараз повертає завершені нелупові sources за isPlaying. Перевір, чи release/вимкнення не обрізає echo. За потреби bounded tail lifetime або shared return, що переживає dry source. Для сови початковий запас 0.6–1 с, уточнити записом. Хвіст входить у бюджет голосів. Після release скидати стан фільтрів: echo сови не переходить на наступний UI-звук.

## 7. Спільна доба для аудіо, світла й рослин

Використати AtmosphereCatalog/atmosphere.json. Не створювати незалежний аудіогодинник або другий day/night bool. Перемога сама не переводить рівень у вечір.

Інтервали нижче взяті з чинних профілів. Wind audio weight — запропоновані стартові аудіоваги після калібрування, а не вже реалізовані значення:

|---|---:|---|---:|---|---|---|
| Ранок | 0.75 | 18–35 с | 0 | off | зараз false | 20–45 с |
| Полудень | 1.00 | 30–60 с | 0 | off | зараз false | 20–45 с |
| Вечір | 0.65 | 60–100 с, тихіше ранку | 0.30 | 120–200 с | true за видимого вогню | 20–45 с |
| Ніч | 0.45 | off | 1.00 | 45–90 с | true за видимого вогню | 35–70 с |

Wind руху 0.18/0.25/0.12/0.08 не копіювати механічно в source.volume. Задати явне відображення сили вітру у чутну вагу.

В одній сцені зміна ваг 3–5 с, фільтрів 1–2 с, fire 0.8–1.5 с. Той самий loop не перезапускати. Для різкої зміни сцени ambient crossfade 0.6–1.2 с під листяним перекриттям; тимчасово рахувати обидва шари.

Цільовий profile встановлюється атомарно, ваги інтерполюються. Повторне застосування того самого профілю не створює loops і не обнуляє всі таймери. Заборонений вид не запускає нових подій; уже почату фразу завершити м’яко. День/ніч не перезаписують user settings.

## 8. Ритм живого світу

- Один GustStarted → максимум один gust і один rustle. Синхронізувати із видимою хвилею рослин приблизно в межах 100–200 мс.
- Gust триває 4 с і має атаку: початок файлу не дорівнює піку пориву. Узгодити envelope із записом, не обривати його після першого шелесту.
- Дрібна постійна осциляція листя не запускає one-shot. Обрати один доречний anchor.
- Між виразними bird/owl/gust бажано 3–5 с тиші. Під час completion/transition декоративну подію відкласти або пропустити, не накопичувати чергу.
- Bird/owl не повторюють той самий anchor двічі поспіль за наявності альтернатив. Позиція не стрибає під час фрази.
- Перші 10–15 с після входу без сови й несподіваних гучних акцентів; wind/fire можуть плавно звучати відразу.
- One-shot варіація gain ±1 dB, pitch близько ±2–3%, для owl стриманіше. Не модулювати pitch loop щокадру.
- Декоративний RNG відокремити від gameplay RNG; для тестів керований seed. Звук не змінює генерацію/збереження рівня.
- Порожні anchors обробляти без винятків: пропустити подію або дозволений fallback, не автоматично світовий нуль.

## 9. Меню, камера й переходи

MainMenu використовує той самий спокійний ліс із меншою кількістю деталей. Одна wind-петля не перезапускається при кожній панелі.

FoliageDiveTransition володіє двома rustle: контакт листя з об’єктивом і вихід. Прив’язка до нормованого progress/state, не дві незалежні корутини з фіксованим sleep. Кожен маркер рівно один раз навіть при повільному кадрі.

Далекі деталі можна приглушити на 1–2 dB, attack 80–120 мс, release 250–400 мс. UI не заглушати. Чотирисекундний gust не є обов’язковим whoosh кожного переходу.

При довгому loading rustle не зациклюється. Нова сцена отримує emitters після готовності; старі playback очищаються за ownership, global wind не множиться. Reduced Motion допускає один тихий підтверджувальний акцент без інтенсивної панорами.

## 10. Мікс, налаштування й життєвий цикл

Використати QC_Master, явно перевірити bus кожного key. Для chime узгодити UI-призначення з фактичним routing, не покладатися на префікс sfx.

Модель рівня: `definition trim × play scale × user bus/channel × phase weight × temporary duck × spatial attenuation`. Не застосовувати Master двічі. Добові ваги, pause та duck не перезаписують збережену гучність. SetPlaybackScale керує активним playback; прямий source.volume не має конфліктувати з перерахунком bus.

- Ціль Master: близько 3 dB sample-peak запасу в найгіршому збігу fire+gust+UI+completion. True peak перевірити окремо за наявності аналізатора; це ще не виміряний результат.
- Completion duck 0.75 = приблизно −2.5 dB, не «мінус 75%». Старт: attack 100 мс, hold 500 мс, release 900 мс.
- Звичайні taps не приглушують ліс. Політика накладання ducks визначена явно, без нескінченного зниження.
- Wind нижче важливих деталей; crickets не маскують UI; owl не лякає; completion короткий.
- Mute — нуль включно з wet-tail та тестовим click. Після unmute немає backlog і стрибка на повну.
- Перевірити на динаміку телефона й навушниках при низькій гучності, а не лише на моніторах.

Ownership: bootstrap — global bed; сцена — локальні emitters/розклад; transition — свої rustle/duck; UI — відгуки. Повторний start перевіряє чинний handle. Unload скасовує власні таймери, підписки та playback. Не StopAll, який зупинить чужі звуки.

Поточний AudioHandle містить AudioSource, а не захищений playback ID. Старий delayed callback не має зупинити новий звук на повторно використаному source. За потреби generation/token у чинному сервісі та окремий тест; не тримати застарілі handles.

Пауза gameplay зупиняє декоративний scheduler; UI працює. Fade може використовувати unscaled time. При background/audio interruption події не накопичуються. Paused source не вважати завершеним лише за isPlaying=false без урахування політики паузи.

## 11. Телефон: імпорт і бюджети

Не AudioSource на кожне дерево. Використати pool; wet-джерела прогріти, не AddComponent на кожний tap.

| Якість | Активних playback із хвостами | Просторових | Live reverb | Occlusion |
|---|---:|---:|---|---|
| Low | до 8 | до 3 | off | без physics |
| Balanced | до 12 | до 5 | максимум один shared return за потреби | до 2 джерел × 5 Гц |
| High | до 16 | до 6 | один shared return | без безпідставного збільшення |

Це цільові бюджети, не результати профілювання. При переповненні першими пропускати декоративні one-shot. У Unity менше числове Priority означає вищий пріоритет: узгодити поточні значення, щоб ambient не витісняв UI.

Імпорт:

- UI/rustle/twig/placement: Decompress On Load, PCM або ADPCM після A/B.
- Wind/fire: Streaming/Vorbis як старт; порівняти streaming CPU, буфери, затримку першого запуску й пам’ять на пристрої.
- Crickets 8 с mono: близько 0.67 MiB PCM16 у джерелі; runtime representation може бути більшим. Режим обрати за Profiler.
- 44.1 kHz спершу зберегти. 22.05 kHz може змінити високочастотний характер crickets; лише після прослуховування.
- Критичний click готовий до першого UI; background loading перевіряє AudioClip.loadState.
- Петлі тестувати після мобільного encoding/import. Dual-source crossfade рахується як два голоси.
- Low за потреби може отримати контрольовану offline wet-похідну owl; такого ресурсу зараз не підтверджено.

Профілювати Audio/DSP/Streaming CPU, voices, пам’ять, GC і перший playback на фізичних пристроях. Орієнтир для доданого коду координації <0.5 мс main thread і 0 B GC у звичайному кадрі; це бюджет, не вимір і не заміна DSP-профілювання. Не оголошувати мобільну оптимізацію доведеною лише в Editor.

## 12. Порядок реалізації

1. Звірити keys/GUID, callbacks, mixer і поточні виправлення.
2. Прослухати 23 джерела, окремо loops і mono-суму; позначити непридатні кандидати.
3. Скоригувати потрібні loop/transient/DC проблеми на похідних або у власному генераторі.
4. Відкалібрувати сухі wind/fire/crickets/UI.
5. Усунути duplicate events; перевірити ownership/handles/pool; placement прив’язати до результату commit.
6. Перевірити listener, панораму, дистанції й anchors.
7. Зв’язати добу та GustStarted, зробити плавні ваги без restart однакових loops.
8. Налаштувати owl echo й tail; лише потім оцінити користь reverb.
9. Узгодити transition, pause, mute, loading, background і settings.
10. Виконати тести, слухову перевірку й профілювання.

Дотримуватися чинного джерела конфігурації та content pipeline. Не вводити ще один незалежний JSON/SO зі суперечливими параметрами. Якщо змінюється авторство конфігурації — узгодити генерацію, runtime loading і валідацію. Додавання поля в JSON без споживача не є реалізацією.

## 13. Критерії приймання

| Перевірка | Очікуваний результат |
|---|---|
| Catalog | Усі 17 keys доступні, немає missing clips |
| Дії | Один основний відгук на прийнятий жест; невдалий commit без success |
| Completion | Основний акцент один; chime максимум один; панель не повторює перемогу |
| Простір | Ліво/право відповідає екрану; fire на вогні; джерела не стрибають |
| Listener | Рівно один активний у меню, gameplay і переході |
| Loops | 10 повторів без чутного кліку, провалу або обриву |
| Доба | Ранок → полудень → вечір → ніч → ранок плавно; вночі новий bird не стартує |
| Вітер | Один gust відповідає видимій події, немає storm із rustle кожного листка |
| Echo/pool | Потрібний хвіст не обрізається; ефект не переходить на UI |
| 30 переходів | Не ростуть loops/sources/listeners/підписки; duck повертається |
| Handle reuse | Старий delayed stop/scale не зачіпає новий playback того самого source |
| Pause/background | Немає backlog, стрибків рівня чи помилкового release |
| Mute/settings | Ваги й ефекти поважають user volume; значення збережені |
| Пристрій | Голоси/DSP у бюджеті, UI не витісняється; звіт містить модель і build |
| Комфорт | 10 хвилин у навушниках і на динаміку без настирливих повторів, різких піків і писку |

Автоматичні тести: duplicate events, same-profile idempotence, anchor fallback, owner cleanup, listener count, handle reuse, mute/duck composition. Вони не замінюють прослуховування.

Результат роботи агента: реалізовані зміни, фактична мапа прив’язок, скориговані ресурси/параметри, результати перевірок, запис 30–60 с кожної доби й одного переходу, чесно зазначені неперевірені пристрої та обмеження. Не видавати цей промпт або налаштовані sliders за вже завершене звучання.
