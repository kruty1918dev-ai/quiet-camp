# Промпт для ШІ: живі частинки й спокійна природа QuietCamp

Ти — агент-виконавець, який допрацьовує атмосферні ефекти QuietCamp у Unity 6 / URP. Реалізуй описану нижче систему, спираючись на наявний код. Документ самодостатній: тут визначено ефекти, розташування, параметри, добу, зв’язок зі звуком, обмеження й критерії приймання.

## 1. Якого відчуття потрібно досягти

Маленька галявина живе своїм спокійним життям: іноді проходить легкий вітер, трава нахиляється, крона відповідає із невеликою затримкою, з куща зривається один листочок. Зранку кілька порошинок стають видимими у світлі. Увечері біля кущів з’являються світлячки. Над видимим вогнищем підіймається тонкий дим. Уночі цвіркуни чути з трави.

Головний об’єкт уваги — рішення гравця та його табір. Ефекти помітні, коли зупинитися й придивитися, але не вимагають уваги. У природних подій є паузи. Не перетворюй кадр на постійний дощ листя, пилу, іскор і світлячків.

Частинки доповнюють освітлення й композицію, але не виправляють плаваючі дерева, замале поле, помилки орієнтації чи перевантажений HUD. Не компенсуй їх додатковим туманом або bloom.

### Конкретні місця для перевірки й виправлення

1. Scale(balanced, low, high, tier) зараз на High використовує Max(balanced, high). При balanced=0 це може ввімкнути денні світлячки або нічний пилок. **Нуль добового профілю означає вимкнено на будь-якій якості.** Спочатку gate профілю, потім quality cap.
2. maxParticles із нижньою межею 1 не є способом вимкнути ефект. При semantic budget=0 вимкнути emission/manual Emit; за потреби плавно завершити живі частинки.
3. ApplyProfile явно оновлює dust/fireflies/smoke/mist. Перевір також leaves/nearLeaf та зміну якості без повторного Configure і без дублювання систем.
4. NearLeaf зараз використовує UnityEngine.Random.value для таймера. Замінити на окрему декоративну послідовність, що не зачіпає gameplay random.
5. NearLeaf position обчислюється через camera.position.y. Це не універсальна глибина від камери. Перевір view-space depth, frustum, нахил камери й реальне уникнення ProtectedViewport.
6. Mist зараз має накопичувальне зміщення position += ... . Обмежити відхилення від початкового anchor або зробити плавний wrap із crossfade; туман не має назавжди залишити кадр.
7. У smoke до X і Z додається однакова додатна gust-складова. Узгодити порив із directionXZ, а не з фіксованою діагоналлю світу.
8. Reduced Motion перевіряється в логіці листя; перевір решту вже живих систем і glow світлячків. Вимкнення emission саме по собі не зупиняє наявні частинки.
9. Поточний atlas працює через texture-sheet grid. Перевір кожен із чотирьох варіантів у кадрі; не оголошувати весь atlas помилкою лише через наявність Texture2D замість Sprite.

Це вимоги до перевірки реалізації, а не твердження про вже виконані виправлення.

## 3. Просторові зони й захист гри

Познач c = реальний розмір однієї клітинки поля. Усі наведені нижче world-space розміри множаться на c. Екранні розміри задаються окремо — не змішувати їх із метрами.

Розділити місця ефектів за призначенням:

- **Далекий план:** між краєм галявини й лісом, позаду gameplay. Тут тонкий ранковий серпанок.
- **Край галявини:** кущі, групи трави, крони. Тут основне листя, пилок і світлячки.
- **Ігрове поле:** захищена зона. Лише причинний ефект конкретного об’єкта, наприклад дим його вогнища. Без декоративної завіси перед клітинками.
- **Ближні краї кадру:** рідкісний великий м’який лист. Він частково обрізаний краєм, не пролітає через центр поля.

ProtectedViewport отримувати від чинної композиції. Для великих ближніх частинок врахувати їхній спроєктований радіус і запас 12–20 логічних одиниць навколо поля. Перевіряти траєкторію, а не тільки стартову точку. Якщо безпечного місця немає — пропустити появу.

Усі джерела мають коректні anchors. Fire — видиме вогнище, fireflies — кущі/трава, leaves — крона або upwind край. Не спавнити листя з центра намету, пилок з-під UI чи дим із світового нуля.

World particles відмальовуються під UI та з коректною глибиною відносно об’єктів. Не малювати їх поверх дверей, маркерів правил і ghost placement через ZTest Always. Для ближнього screen-space шару окремо діє protected mask; не вимикати depth test усім системам.

## 4. Мапа ефектів і початкові параметри

Це стартова художня настройка, яку треба перевірити на реальному полі. Cap — максимум одночасно живих частинок, а не бажана постійна кількість.

| Ефект | Де / коли | Початковий характер |
|---|---|---|
| Листя середнього плану | Upwind кущі й край крон, усі доби | Рідкісні одиночні листки; повільний дрейф і падіння |
| Ближній лист | Тільки край кадру, рідко | Один більший м’який силует, без перетину поля |
| Пилок / порошинки | Локальні освітлені ділянки, ранок/полудень | Кілька ледве видимих теплих точок; не сніг |
| Світлячки | Над травою й біля кущів, вечір/ніч | Повільні короткі траєкторії з асинхронним світінням |
| Дим | Над активним видимим вогнем | Тонкі м’які клаптики, підйом і відхилення за вітром |
| Жаринки | Чинне багаття | Поодинокі теплі точки, швидко згасають |
| Ранковий серпанок | Позаду галявини, ранок | Один прозорий далекий шар; не fullscreen veil |
| Реакція на взаємодію | Реально існуюча дія з декором, якщо є | Опційно один малий rustle/лист; не burst на кожен tap |

### 4.1. Листя середнього плану

- Розмір 0.08–0.18c; lifetime 6–10 с.
- Бічна швидкість 0.15–0.35c/с уздовж вітру; падіння 0.04–0.10c/с.
- Стартова висота 0.8–2c біля доречної рослини; для низького куща нижча.
- Повільний оберт близько ±20–40°/с з різними фазами; без спіннера.
- Спокійна частота приблизно один лист на 12–25 с на всю сцену. Порив може додати 1–2, лише за вільного бюджету.
- Fade-in 0.25–0.4 с, fade-out 0.8–1.2 с. Початкова opacity 0.55–0.8, уточнити за текстурою.
- Лист зберігає одну форму весь lifetime. Ніякого перемикання між гілочкою й листком як flipbook.
- При наближенні до землі fade до контакту або проста аналітична висота без фізичних collision. Немає накопичення тисяч нерухомих листків.
- Порив не робить бурю й не збільшує швидкість на порядок.

### 4.2. Ближній лист

- Balanced/High: максимум один одночасно. Low: вимкнено.
- Інтервал 30–60 с; не обов’язково кожний інтервал, якщо поле/панель не лишають місця.
- Екранна ширина приблизно 3–6% viewport width. Підібрати world size через проєкцію, не фіксованою відстанню від висоти камери.
- Lifetime 3–5 с; траєкторія вздовж зовнішніх 8–12% кадру. Часткове обрізання краєм природне.
- М’якість закладена в підготовлену похідну текстуру; runtime DOF не потрібний.
- Жодного нового близького листа під час drag, модального вікна чи переходу.
- Не використовувати чотири повністю видимі листки по центру як демонстрацію atlas: це вже було невдалим виглядом переходу.

### 4.3. Пилок і порошинки

- Ранок виразніший, полудень стриманіший, вечір/ніч — вимкнено.
- Локальні об’єми біля освітленого краю; не рівномірний box на весь екран.
- Розмір 0.015–0.045c; lifetime 4–7 с; drift 0.01–0.04c/с плюс мала частка вітру.
- Opacity орієнтовно 0.06–0.16. Теплий кремовий колір, без яскраво-білих дисків.
- Emission обирати з lifetime і бажаної кількості: rate ≈ desired alive / average lifetime. Cap сам по собі не задає красивого ритму.
- Без trails, collision, світла й звуку для кожної точки. Не робити їх схожими на сніг або комах, що атакують табір.

### 4.4. Світлячки

- Вечір/ніч; висота 0.15–0.8c над травою, переважно біля крайових кущів.
- Видимий core 0.02–0.04c, glow 0.05–0.09c; без Point Light.
- Lifetime 8–14 с; швидкість 0.03–0.08c/с. Рух у невеликій області навколо home anchor, без синхронних орбіт.
- Світіння плавне, цикл 2.5–5 с, різні фази й тривалі паузи; без різкого блимання.
- Колір теплий жовто-зелений, стриманий. Читабельний без bloom; не пересвічує намет.
- Достатньо 2–3 видимих точок на Balanced. Припинити emission на світанку, поточні завершити м’яко.
- Світлячки не є цвіркунами. Не синхронізувати кожен спалах із chirp і не додавати звук світіння.

### 4.5. Дим

- Тільки коли fireActive і існує правильний fire anchor.
- Lifetime 2.5–4.5 с; size 0.15–0.3c на старті → до 0.45–0.7c наприкінці.
- Підйом 0.15–0.3c/с; відхилення directionXZ × wind strength × коефіцієнт. Порив підсилює ту саму спрямовану складову.
- Opacity 0.04–0.10; сіро-теплий удень, приглушений прохолодний уночі. Не чорний дим пожежі.
- Один emitter, без додаткового «диму на фоні» поверх того самого вогню.
- Після згасання — stop emission і природне завершення хвоста. При scene unload повний cleanup.
- Дим за об’єктом має коректно перекриватися геометрією. Якщо покриває входи, зменшити footprint/opacity.

### 4.6. Жаринки

Використати чинний ефект багаття, якщо він є; інакше додати один мінімальний emitter у тому самому owner. Розмір 0.01–0.025c, lifetime 0.6–1.4 с, швидкість вгору 0.2–0.45c/с. Теплий amber → м’який orange → прозорість. Без нескінченних світлих ліній, collision і sub-emitters. Не більше одного маленького burst 1–2 жаринки раз на 4–9 с; узгодити з наявним emission, не додавати поверх нього.

### 4.7. Ранковий серпанок

Один дальній quad або наявний mist-шар. Це не сотні alpha-particles і не справжній volumetric fog. Opacity 0.025–0.06, дуже повільне обмежене зміщення. Не перекриває UI/поле, не створює прямокутних швів. Вимикається на Low. На інших добах off за замовчуванням; ніч не потребує автоматичного густого туману.

## 5. Добові профілі й ліміти

Наявні профілі: morning, noon, evening, night. Користуватися ними; не незалежним таймером частинок. Значення нижче — бажаний старт Balanced з урахуванням наявного конфігу:

| Доба | Листя | Ближній лист | Dust | Fireflies | Smoke | Mist | База вітру / пориви |
|---|---:|---:|---:|---:|---:|---|---|
| Ранок | cap 4 | cap 1 | cap 6 | 0 | 0 без вогню | on | 0.18 / 20–45 с |
| Полудень | cap 4 | cap 1 | cap 4–6 | 0 | 0 без вогню | off | 0.25 / 20–45 с |
| Вечір | cap 4 | cap 1 | 0 | cap 3 | cap 2 за вогню | off | 0.12 / 20–45 с |
| Ніч | cap 2–4 | cap 1, рідше | 0 | cap 2 | cap 2 за вогню | off | 0.08 / 35–70 с |

Не змінювати фазу рівня тільки заради демонстрації частинок. Художні параметри не впливають на shadeMask, правила або доступність клітинок.

На зміні профілю спочатку заборонити нові неактуальні частинки, потім плавно завершити старі за 1–2 с або їхнім коротким lifetime. Не залишати денний dust ще 10 с у нічному кадрі. При повторному застосуванні того самого профілю нічого не дублюється.

Quality може змінити щільність дозволеного ефекту, але **не може ввімкнути заборонений добою ефект**. Правило: phase disabled → count 0 → emission 0 → manual Emit заборонений. Лише після цього застосувати tier cap.

## 6. Один вітер для дерев, трави, листя, диму й звуку

Перевикористати WindSim.Snapshot: DirectionXZ, BaseStrength, GustEnvelope, Strength, PhaseSeconds. Advance(dt) викликає один owner один раз за visual frame. Споживачі лише читають стан. Не створювати власний gust у кожному emitter.

Чинна envelope: attack 0.8 с, hold 0.5–1 с, release 1.5–2 с; додаткова сила 0.15–0.25. Напрям змінюється плавно, не швидше близько 15° за 30 с. При переналаштуванні зберегти спокійний характер.

Послідовність одного пориву:

| Час від початку | Видимий / звуковий результат |
|---|---|
| 0–0.8 с | Вітер набирає силу, upwind трава нахиляється; один тихий gust audio |
| 0.2–1.2 с | Крони м’яко реагують, один rustle біля доречного куща за cooldown |
| 0.4–1.0 с | Може відірватися 1 лист, якщо є бюджет і безпечна траєкторія |
| 1.3–3.8 с | Порив стихає; трава й квіти спокійно повертаються |
| Далі | Тиша до наступної події; не запускати компенсаційні bursts |

Для просторової хвилі використовувати world position і той самий visual clock. Не затримувати сусідні рослини на кілька секунд на маленькому полі. Корені нерухомі: нижні 30–40% стовбура майже не деформуються. Крона 0.5–1.2% висоти у спокої, до 2% на пориві; трава приблизно 2–5° у спокої, до 8° на пориві; квіти реагують трохи повільніше. Це початкові художні величини, що залежать від mesh.

Не рухати collider, raycast-площину або логічну тінь разом із shader-sway. Частинки підсилюють реакцію рослин, а не замінюють її.

## 7. Звуки: цвіркуни й дрібні причинні акценти

| Явище | Наявний key | Правило |
|---|---|---|
| Фоновий вітер | ambience.wind | Чинна тиха петля; не дублювати з particle owner |
| Порив | ambience.gust | Один звук на GustStarted; зараз інтеграція вже є у CampSceneHost |
| Листя біля куща | sfx.rustle | Не кожна частинка; максимум один тихий акцент на порив, cooldown ≥10 с |
| Цвіркуни | ambience.crickets | Вечірня вага 0.3, нічна 1; удень 0; одна петля |
| Птах | ambience.bird | Далека крона, ранок/полудень; не потрібна постійна зграя |
| Сова | ambience.owl | Рідко ввечері/вночі, без обов’язкового видимого персонажа |
| Вогонь | ambience.fire | Петля чинного вогню; не звук на кожну жаринку |

Цвіркуни — передусім акустичний шар із трави. Не робити літаючих зелених «цвіркунів». Детальна видима комаха для загального плану не потрібна. Якщо колись з’явиться окремий близький ракурс — це окреме обґрунтоване завдання.

Particle callback не керує аудіосервісом для кожного spawn/death. Семантичні події й audio owner лишаються централізованими. Загальна сила вітру впливає на реакцію світу, але не множить усі звуки на один жорсткий коефіцієнт.

## 8. Матеріали, atlas і підготовка графіки

Для листя використати leaves.png. Одна частинка → одна клітинка 2×2 → незмінний варіант протягом життя. Створити контрольний показ усіх чотирьох варіантів перед художнім тестом; перевірити UV, padding і відсутність сусіднього листка в тому самому quad.

Наявний startFrame 0..3.99 не замінювати навмання на нормований 0..1: значення й результат перевіряти за API і контрольними кадрами. FrameOverTime не анімує зміну форм. Atlas для world particle і Sprite для UI transition — різні споживачі, перевіряти окремо.

Наявної м’якої dot-текстури достатньо для dust/fireflies і початкового smoke. Якщо потрібна інша форма, створити нейтральний м’який ресурс без тексту й рамок. Не генерувати зайвий набір графіки до оцінки чинних ресурсів.

- Leaf/dust/smoke: простий URP unlit transparent, ZWrite Off; world-ефекти мають коректний depth test.
- Для straight alpha: SrcAlpha / OneMinusSrcAlpha. Якщо обрано premultiplied, конвертувати та узгодити blend, не множити alpha двічі.
- Firefly core/glow — стриманий alpha або контрольований additive. Жодних окремих lights.
- Без real-time DOF, distortion, refraction, soft-particle depth sampling і depth texture лише заради декору.
- Без trails, physics collision, lights, sub-emitters у базовій системі.
- Не material на кожну частинку; спільні матеріали за типом і коректний vertex tint.
- Перевірити краї на світлому й темному фоні: ніяких білих/чорних обводок або видимого прямокутника текстури.
- Bounds враховують реальну траєкторію; particle не зникає при повороті/русі камери лише через малий bounds.
- Імпортна компресія — після порівняння на пристрої; не погіршити м’який alpha заради мінімального розміру.

## 9. Взаємодія, pause, reduced motion й переходи

Під час drag припинити нові ближні листки; середній/далекий декор лишається тихим і не перекриває ціль. Частинки не мають Collider, raycastTarget або gameplay interaction.

Pause: декоративний scheduler і рух заморожуються згідно єдиному presentation pause, UI працює. Немає незалежних таймерів, що запускають burst позаду налаштувань. Resume без накопичених подій або великого dt.

Background: зупинити декоративний час. Після повернення не симулювати хвилину пропущених частинок. Рідкісні події планувати заново без гуртового spawn.

Reduced Motion:
- nearLeaf off, leaf drift off або завершення вже живих за 0.2–0.4 с;
- fireflies залишаються рідкими майже нерухомими точками з постійним слабким світлом, без pulse;
- mist нерухомий; dust можна вимкнути;
- smoke/embers мінімальні, без різких bursts; допустимо вимкнути за обраною політикою;
- дерева/трава поважають той самий прапорець;
- природний звук не вимикається автоматично разом із візуальним рухом.

Під час scene transition новий nearLeaf не запускається. Перехід має власника й окремі великі маси листя; gameplay systems не повинні створювати другу завісу. Дотриматися спільного бюджету. Не використовувати центральну композицію з окремих цілих листків на однотонній заливці як «занурення в кущ».

При resize/orientation update повторно обчислити frustum, anchors screen-edge і protected area після актуального layout. Не виправляти перевернуту орієнтацію поворотом emitter або фону на 180°.

## 10. Бюджети, overdraw й мобільна оптимізація

Верхні межі одночасно живих частинок, лише для ефектів, дозволених поточною добою:

| Ефект | Low | Balanced | High |
|---|---:|---:|---:|
| Середнє листя | 2 | 4 | 6 |
| Ближній лист | 0 | 1 | 1 |
| Dust | 0 | 6 | 8 |
| Fireflies | 0 | до 3 | до 5 |
| Smoke | 1 за вогню | 2 за вогню | 3 за вогню |
| Embers чинного вогню | 2 | 3 | 5 |
| Mist | 0 | 1 quad | 1 quad |

Гранична сума particle caps 5 / 19 / 28, але не всі дозволені одночасно через добові gates. Mist рахується окремо; базові meshes полум’я й статичні foreground/rear теж окремо. Наявні іскри включити в ці числа, а не додавати ще стільки ж.

При тиску на бюджет першими прибрати dust, потім nearLeaf, потім зайвих fireflies. Не збільшувати щільність High тільки для помітної різниці preset.

- Не створювати/знищувати systems/materials на кожній події. Побудова один раз, оновлення параметрів без GC у звичайному кадрі.
- Один бюджет на сцену; не повний ліміт для кожного дерева.
- Не робити fullscreen transparent quads для dust/smoke. Їхня прозора площа має бути близька до видимого ефекту.
- На Balanced орієнтир площі великих ближніх/smoke ефектів у звичайному кадрі до 10% екрана, без урахування окремого далекого mist; поле лишається чистим. Це ціль композиції, не замір GPU.
- Перевірити overdraw, draw calls, GC, CPU/GPU delta, пам’ять і теплову стабільність на фізичному телефоні.
- Початковий бюджет додаткового CPU-коду атмосфери <0.5 мс/frame, GPU частинок <1 мс на цільовому пристрої; це запропоновані межі, а не доведені результати.
- Якщо перевищено: спочатку прибрати зайву прозору площу й системи, потім зменшувати кількість. Малий count не гарантує низького overdraw.
- Offscreen culling не має спричиняти великий catch-up burst при поверненні камери.

## 11. Життєвий цикл і конфігурація

Використати чинні profile-поля; нові художні параметри зберігати в узгодженому джерелі конфігурації QuietCamp. Не створювати паралельний JSON/SO, який суперечить atmosphere.json. Validate: невід’ємні count/rate, min≤max, коректні phase IDs, anchors і наявні ресурси.

Повторні ApplyProfile, quality change, Reduced Motion, SetFire не створюють новий набір систем. OnDestroy відписує GustStarted, завершує власні particles та звільняє лише створені runtime materials/textures. Не Destroy ресурсу, завантаженого й спільно використаного іншими об’єктами.

Не зберігати декоративні частинки у gameplay save. Сцена може відновити атмосферу з phase та visual seed. Не викликати Resources.UnloadUnusedAssets посеред жесту.

Якщо shader/texture недоступні: вимкнути відповідний декор з однією діагностикою; гра лишається доступною. Не рожевий material, не exception loop і не непрозорий квадрат на весь кадр.

## 12. Порядок роботи агента

1. Перевірити чинні owners, systems, shader, профілі, atlas та існуючі fire particles.
2. Виправити semantic zero на High, декоративний RNG, anchors/view-space depth та bounded mist.
3. Забезпечити protected area, depth, відсутність raycast-перехоплення і дублювання.
4. Налаштувати ранок лише з листям/dust, потім полудень; додати вечір/fireflies/smoke і ніч.
5. Узгодити єдиний gust із рослинами, leaf release й наявними звуками.
6. Перевірити alpha, softness, scale на фізичному розмірі екрана.
7. Завершити pause/reduced motion/lifecycle/quality.
8. Провести порівняння «ефекти off/on», тести та профілювання. Не збільшувати кількість ефектів заради демонстрації.

## 13. Приймання

| Перевірка | Умова успіху |
|---|---|
| Ранок/полудень | Легке листя/dust, без світлячків і диму неіснуючого вогню |
| Вечір/ніч | Рідкі світлячки, коректні smoke/embers; немає денного пилку |
| High zero gate | Будь-який phase count=0 лишається 0 на High |
| Atlas | Кожен із 4 варіантів показується окремо; форма не змінюється протягом lifetime |
| Поле | Всі крайові клітинки, входи й ghost читабельні під час пориву |
| Причинність | Один gust, одна узгоджена хвиля, максимум один тихий rustle; не звук на spawn |
| Ближній лист | Не перетинає protected area, не стартує під час drag/modal/transition |
| Дим | Походить із видимого вогню, дрейфує за напрямком вітру, не фіксованою діагоналлю |
| Тиша | У кадрі є паузи; немає постійної завіси чи синхронного blinking |
| Reduced Motion | Працює для вже живих ефектів без reload; немає нового близького прольоту |
| Pause/background | Без catch-up, таймерних bursts і стрибків положення |
| 30 переходів | Не ростуть systems/materials/subscriptions; немає старих emitters у новій сцені |
| 10 хвилин | Mist не зникає назавжди, leaf count не накопичується, RNG гри незмінний |
| Телефон | Записані CPU/GPU/overdraw/voices за реальним пристроєм; недоступні тести позначені |

Автоматичні тести: profile zero across tiers, ідемпотентність ApplyProfile, quality update, fire gate, owner cleanup, reduced-motion emission і незалежність gameplay RNG. Візуальні параметри перевірити записом, не тестом, який лише повторює константи.

Агент має надати короткий результат: змінені файли, фактичні caps і профілі, відео 45–60 с кожної доби з принаймні одним поривом, демонстрацію Reduced Motion та off/on, результати профілювання й чесно зазначені неперевірені умови. Прискорення для демонстрації допустиме лише у debug; фінальний запис також показує реальний темп.

## 14. Технічна опора

Texture Sheet Animation може використовувати grid або список sprites; startFrame задає стартовий кадр. Перевірити саме встановлену версію Unity: [TextureSheetAnimationModule.mode](https://docs.unity3d.com/ja/current/ScriptReference/ParticleSystem.TextureSheetAnimationModule-mode.html), [TextureSheetAnimationModule.startFrame](https://docs.unity3d.com/ja/current/ScriptReference/ParticleSystem.TextureSheetAnimationModule-startFrame.html).

Усі художні числа й бюджети вище — початкові рекомендації для QuietCamp, не виміряна продуктивність і не універсальні налаштування Unity. Створення цього документа не означає, що код або ефекти вже змінені.
