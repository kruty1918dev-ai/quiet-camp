# Ознайомлення з політикою на старті

Перевірено 2026-10-04. Поточний документ — **позначена заглушка**, реквізити
видавця та посилання залишені порожніми за вказівкою власника проєкту.

Boot показує коротке ознайомлення, повний текст у прокручуваній панелі та місце
для посилання на оригінал. «Ознайомився, продовжити» зберігає локальний запис
і відкриває меню. «Вийти» або системна дія назад завершує player; у Unity Editor
залишає Boot для перевірки. Відмова нічого не приймає. Наступний запуск знову
показує панель. Після успішного запису незмінний документ пропускається.

## Юридичне рішення

Google Play вимагає політику в Play Console та її посилання/текст у самій грі.
Ознайомлення з документом саме по собі не є згодою на всі види обробки.
Неочікуваний збір даних потребує відповідного окремого розкриття і вибору.
[Google Play User Data](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en).

Якщо підставою обробки є згода, вона має бути добровільною, конкретною та
поінформованою. Обов’язкова кнопка «погодься на аналітику або вийди» створює
проблему добровільності. Тому Boot фіксує **ознайомлення**, а додаткова аналітика
залишається окремим добровільним вибором; відмова від неї не закриває гру.
[EDPB, настанови 05/2020](https://www.edpb.europa.eu/documents/guideline/guidelines-052020-on-consent-under-regulation-2016679_en).

Це висновок для проєктування інтерфейсу, а не висновок про законність усіх майбутніх
SDK чи релізу у всіх країнах. Видавець має визначити правові підстави, реальні
процеси й правила для підлітків у вибраних країнах перед публікацією.

## Технічний порядок

1. Boot читає локальні збереження та мову, фіксує орієнтацію.
2. UnityHTML читає документ і показує власну ігрову панель. До підтвердження не
   створюється `GameServices`, не викликаються фабрики optional SDK, не
   відновлюється згода на аналітику й не завантажується MainMenu.
3. Після явного натискання зберігається revision, SHA-256 вмісту, мова, UTC-час
   та ознака чернетки. Збій запису залишає панель відкритою та відновлює старі
   значення в пам’яті. Сам факт показу або завантаження не записує ознайомлення.
4. Потім Boot ініціалізує гру звичайним шляхом. Поля consent не змінюються.

Старі збереження не мають цього запису і покажуть панель один раз. Зміна revision,
вмісту або переходу від чернетки до опублікованого документа показує її знову.
Переклади з іншим вмістом теж мають інший hash. Прогрес, кемпінги та косметика
залишаються у поточному save slot, новий паралельний формат збереження не введено.

## Як замінити заглушку

Файл `QuietCamp/Assets/QuietCamp/Resources/QuietCamp/privacy_content.json`:

- `draft: true` зараз примусово вимикає URL-запити. Локалізовані uk/en/de
  документи та короткі тексти позначені чернетками. Публічне посилання вимкнене.
- Для релізу заповнити `legal.json`: видавець, контакт, HTTPS-політика, revision
  і дата. Ці дані досі залишені порожніми.
- Опублікувати погоджені мовні версії. У `document.variants` додати остаточні
  HTTPS URL, мову, однаковий із `legal.json` revision, формат і selector.
  `format`: 0 — текст, 1 — HTML, 2 — JSON API.
- У `document.allowedOrigins` явно вказати точні дозволені HTTPS origins.
  Перенаправлення вимкнено: конфігурувати остаточні URL.
- `summaries` містять окремо погоджені короткі тексти з language та revision.
  Повний текст не скорочується автоматично. Якщо короткого тексту немає,
  відображається повний.
- `bundledBody` має містити погоджену офлайн-копію відповідного revision та мови.
  Якщо офлайн-ознайомлення з нею неприйнятне для вашого процесу, прибрати копію.
- Лише після цього поставити `draft: false`. Невідповідний revision або
  незаповнені реквізити дають відновлювану помилку Boot, а не фальшиве прийняття.

Стандарт API: `{ "body": "…", "language": "uk", "revision": "…", "format": "text" }`.
Для HTML API повертає `format: "html"`, а selector виділяє документ. Зміни тексту
сервера читаються при наступному запуску; новий hash потребує ознайомлення знову.
Немає прихованого фонового опитування. Рекомендовано стабільний API або окремий
HTML `article` із документом, без меню сайту та динамічного JavaScript.

## Мова, мережа та оформлення

На першому запуску використовується мова пристрою через наявний модуль локалізації.
За наявності збереження зберігається вибір гравця. Точна мовна версія → нейтральна
мова → англійська; якщо потрібного перекладу немає, видно мову оригіналу. Юридичний
текст не перекладається машинно й не переписується непомітно.

UnityHTML перетворює HTML на інертні абзаци/заголовки: локальний CSS відповідає
за стиль, нові абзаци автоматично отримують його. Оригінал зберігається окремо,
скрипти та атрибути сайту не виконуються. Це не браузер; перед публікацією
звірити слова витягнутого тексту з канонічним документом.

HTTPS завантаження має ліміт розміру й часу. Некоректна відповідь не затирає
попередню перевірену копію. Порядок: мережа → віковий перевірений кеш → погоджена
локальна копія. Збережена копія позначається в панелі. Без будь-якого документа
продовження вимкнено, доступні повторне завантаження та вихід.

Кеш документів знаходиться в `qc_policy_cache`, не містить ідентифікаторів гравця.
Сервер документа може бачити IP запиту; це слід врахувати в опублікованій політиці
та конфігурації логування. Зараз із чернеткою таких запитів немає.

Документація універсального модуля:
[UnityHTML: remote content](https://github.com/kruty1918dev-ai/com.kruty1918.moyva.unityhtml/blob/main/Documentation~/remote-content.md).
