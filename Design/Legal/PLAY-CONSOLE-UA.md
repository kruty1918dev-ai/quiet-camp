## 2. Блокер для нових персональних акаунтів — закрите тестування

Якщо Play Console-акаунт створений після 13.11.2023 (Personal):

- **≥12 тестерів, opt-in безперервно ≥14 днів** у закритому треку — тільки тоді відкривається Production.
- Тестери потребують Google-акаунтів; списки — email або Google Groups (до 2000 осіб/список, 50 списків/трек).
- Після виконання критерію — заявка на production доступ з відповідями про дизайн/тестування на Dashboard.
- Практичний план: [ЗАПОВНИТИ день старту й подачі заявки]. Список тестерів зберігати приватно в Console/робочій системі, не в репозиторії юридичних документів.

[App testing requirements for new personal accounts](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en-en).

## 4. Пункти майбутньої подачі — без запуску білду

- **Target API level**: станом на 2026-10-04 нові mobile-застосунки/оновлення з 31.08.2026 мають target API **36+**; можливу extension перевірити в Console. У поточному файлі проєкту Min API **26**, target **35**. Перехід і сумісність ще не перевірено; не позначати цей пункт виконаним. [Актуальні строки й винятки](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en-en).
- **AAB, не APK**: Play приймає тільки Android App Bundle для нових застосунків.
- **Play App Signing**: Google тримає ключ підпису релізу. Upload-ключ = окремий: [ЗАПОВНИТИ де зберігається; backup ключа + паролів у двох місцях]. Втрата upload-ключа = звернення в підтримку для reset — не фатально, але повільно.
- **64-bit**: у налаштуваннях обраний ARM64; це не доказ фактичного артефакту чи його сумісності. Перевірка конкретного релізу лишається для дозволеного майбутнього процесу подачі.

**Власник заборонив player builds. Цей чекліст не є дозволом на збірку, пакування або встановлення.**

## 5. Регіональні зобов'язання (EEA/DE)

- **DSA / trader status**: визначити за реальною діяльністю/статусом видавця й вимогами Console для обраних територій. Offline або відсутність IAP самі по собі не визначають статус. Публічність контактів перевіряється окремо.
- **Impressum (Німеччина, §5 DDG)**: якщо підтримковий сайт/сторінки хостяться від німецького резидента і є діловим онлайн-пропозицією — потрібен вивід провайдера (ім'я, адреса, контакт). Заготовка: `templates/impressum.de.md`. Мінімально-безпечно: окрема сторінка `/impressum` на сайті політики.
- **Представники GDPR ст.27 / UK**: перевірити застосовність, винятки та establishment фактичного контролера; не робити висновок лише з резидентства розробника. [ЗАПОВНИТИ реальну перевірку]

## 6. Послідовність запуску (стисло)

1. Акаунт + верифікація + контакти (п.1)
2. Реєстрація застосунку, bundle id `com.kruty1918.quietcamp` — не змінюється назавжди
3. Публічні сторінки: policy / data-request / support / impressum — live і перевірені зовнішнім браузером
4. App content декларації (п.3) + Data safety з фактичного релізу
5. AAB з Play App Signing, target API актуальний
6. **Закритий трек → 12 тестерів × 14 днів**
7. Production-заявка → рев'ю → реліз по країнах згідно з регіональною матрицею в `README-UA.md` §5
8. Перед кожним оновленням: повторний звір SDK/даних/країн + нова версія згоди якщо змінилась обробка

- Запускати «увесь світ» без §5 README-UA (регіональна матриця) — Brazil/Canada/US-states мають власні правила
