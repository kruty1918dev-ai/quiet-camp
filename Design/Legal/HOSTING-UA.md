# Хостинг публічних юридичних сторінок

Play вимагає: публічний HTTPS-URL, без входу, без геоблоків, не PDF, сторінка не редагується відвідувачами. URL з Console і в грі має вести на той самий документ.

## Варіант — статичний GitHub Pages

GitHub Free підтримує Pages для публічних репозиторіїв; підтримка приватних залежить від тарифу. За потреби юридичні сторінки можна розмістити в окремому публічному репозиторії, залишивши код гри приватним. Сам генератор не створює репозиторії й не змінює їх видимість. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

Структуру готує `tools/legal_site.py` локально. Публікується лише перевірений strict-кандидат; preview лишається чернеткою:

```
docs/                        # GitHub Pages source (Settings → Pages → deploy from /docs)
  index.html                 # список документів + дата оновлення
  privacy-uk.html
  privacy-en.html
  privacy-de.html
  data-request-uk.html
  data-request-en.html
  data-request-de.html
  support-en.html
  support-uk.html
  support-de.html
  terms-en.html
  terms-uk.html
  terms-de.html
  impressum-de.html          # якщо застосовно до видавця/сайту
  style.css
  robots.txt                 # не блокувати індексацію політики
  preparation.json           # редакція, хеші вихідних документів, результат перевірки
```

URL можуть бути `https://<org>.github.io/quiet-camp/privacy-uk.html` або на власному домені. Генератор не додає аналітики, JavaScript, зовнішніх шрифтів чи реклами. GitHub Pages журналює IP відвідувачів для безпеки навіть без входу; це треба врахувати в політиці сайту й перевірці обробника. Для іншого хостера перевірити його фактичні журнали/строки. [GitHub Pages — data collection](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection).

## Підготовка без публікації

Запускати з кореня репозиторію; ці команди не запускають Unity і не створюють player build.

```sh
python3 tools/legal_site.py --output /tmp/quietcamp-legal-preview
python3 -m unittest discover -s tools -p test_legal_site.py -v
```

Preview позначений **DRAFT / ЧЕРНЕТКА / ENTWURF**, має noindex і `robots: Disallow`. Усі незаповнені поля залишаються видимими; `preparation.json` перераховує проблеми. Шлях виходу має бути новим або порожнім: інструмент не перезаписує схвалені сторінки й не залишає старі файли непомітно.

Після визначення реквізитів:

1. Заповнити `Assets/QuietCamp/Resources/QuietCamp/legal.json` у проєкті `QuietCamp`; центральні поля `{{appName}}`, `{{publisherName}}`, `{{supportEmail}}`, `{{revision}}`, `{{publishedOn}}` підставляються в документи.
2. Скопіювати `Design/Legal/templates/` в окрему папку перевірених джерел. Вручну узгодити реальну обробку, прибрати редакторські примітки й усі placeholders. Не просто стерти їх: заповнити зміст або обґрунтовано прибрати непридатний розділ.
3. Якщо Impressum не застосовується, змінити **копію** `site.json` для релізу й прибрати цей документ після регіональної перевірки. Не публікувати порожній Impressum. Мовну карту теж змінювати лише відповідно до фактичних підтримуваних мов.
4. Узгодити URL у `legal.json` з `urlFields` у `site.json`. За замовчуванням головні посилання — `privacy-en.html`, `data-request-en.html`, `support-en.html`, `terms-en.html`; усередині є мовна навігація. Якщо з’являться акаунти, адаптувати дані/видалення під реальні акаунти або додати окремий документ і змінити mapping.

```sh
python3 tools/legal_site.py --release \
  --source /path/to/reviewed-documents \
  --output /tmp/quietcamp-legal-release-candidate
```

Strict-режим відхиляє чернетки, порожні/неузгоджені ідентифікацію й контакт, неправильну дату/редакцію, відсутню мову, тестові/небезпечні URL, неправильні назви цільових сторінок та небезпечні Markdown-посилання. Перевірка завершується **до запису** кандидатів. HTML екранує вихідний текст; форми або автоматичне надсилання не створюються.

Це механічна перевірка, яка не визначає юридичну повноту, належність домену, доступність URL, правильність перекладу чи справжність реквізитів. Release-candidate також **не означає опубліковано**. Деплой, перевірка чистим браузером і операційна репетиція запиту виконуються окремо.

## Чеклист сторінок перед «знімком» для Pages

- [ ] Усі `[FILL]`/`[ЗАПОВНИТИ]`/`[DECIDE]`/`[ОБРАТИ]` заповнені або видалені; редакторські примітки (**DRAFT**, [ПОТОЧНИЙ РЕЛІЗ]-посилання) прибрані з публічного тексту
- [ ] strict-кандидат генератора; UTF-8, мобільна читабельність, клавіатурна навігація й мови
- [ ] Контакти у сторінках = реально моніторені пошти; форми — реально працюють або їх нема
- [ ] Privacy + data-request доступні з режиму інкогніто без входу (перевірити)
- [ ] URL зафіксовані й не змінюватимуться при оновленнях тексту (старі рев'ю-посилання мають жити)
- [ ] Impressum доступний з кожної сторінки (footer), якщо застосовно
- [ ] Кожна сторінка має дату «Оновлено/Effective» і версію документа
- [ ] Історія версій документів лишається в git (Play може попросити показати, що було чинно на дату)

## Альтернативи (якщо не GitHub Pages)

- Будь-який статичний хостинг (Netlify/Cloudflare Pages/VPS): ті самі вимоги — HTTPS, без входу/геоблоку.
- Не підходять: Google Docs (редагований), PDF-файли, сторінки за логіном, динамічні конструктори з нестабільними URL.

## Що вказувати в Play Console

- **Privacy policy URL**: `…/privacy-en.html` (або локалізований варіант за мовою країни — Play бере один головний URL; локалізація всередині через мовні перемикачі на сторінці)
- **Developer website**: `…/index.html` або `…/support-en.html`
- **Developer email**: [ЗАПОВНИТИ моніторену пошту — буде публічною]
- **Account/data deletion**: поки акаунтів нема — у формі відповідаємо по факту; data-request URL тримаємо опублікованим для прав доступу/видалення технічних даних
