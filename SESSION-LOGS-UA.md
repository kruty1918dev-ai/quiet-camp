# Локальна діагностична Android-збірка

Окремий JSON створюється при кожному холодному запуску гри. Згортання і повернення
продовжують поточний файл. Запис локальний, без автоматичного надсилання.

Файл містить версію гри й Unity, модель телефона та графічний API, переходи між
сценами, відомі UI-команди, вибірки FPS/пам’яті кожні 5 секунд, стан Pro,
кількість пройдених рівнів, типи помилок і назви методів QuietCamp. Для Pro-запитів
зберігаються операція, тривалість, HTTP-код і ознака відповіді Cloudflare 1010.
Паролі, токени, HTTP-тіла, введений текст, повні повідомлення помилок, шляхи,
ідентифікатори пристрою та вміст збереження не записуються. Це журнал діагностики,
а не відеозапис і не повне відтворення всіх дотиків.

Контрольне збереження відбувається кожні 5 секунд і при згортанні. При аварійному
завершенні останні секунди можуть втратитися; `endedNormally: false` означає,
що штатне завершення не зафіксоване. Зберігаються 50 останніх сеансів.
В одному сеансі обмежено 2048 подій і 2048 вибірок; лічильники `droppedEvents`
і `droppedSamples` показують відкинуті старі записи. `writeFailures` показує
невдалі спроби запису. Експортовані копії автоматично не видаляються.

## Як передати файли з телефона

1. На Android 10+ відкрийте налаштування гри і натисніть
   **«Експортувати JSON сеансів у Downloads»**.
2. Дочекайтеся повідомлення про успішне збереження.
3. Під’єднайте телефон до ноутбука, розблокуйте його і виберіть USB-режим
   **«Передавання файлів»**.
4. У Провіднику відкрийте телефон → внутрішня пам’ять → **Download → QuietCamp**.
   Скопіюйте `session-*.json` і передайте їх для аналізу.

На Android 8/9 або при невдалому експорті використовуйте власний ADB із дозволеним
USB debugging. Після підтвердження запиту налагодження на телефоні:

```powershell
adb devices
adb -s SERIAL pull /sdcard/Android/data/com.quietcamp.game/files/session-logs ./QuietCamp-session-logs
```

Замініть `SERIAL` на серійний номер свого телефона з `adb devices`.
Збережіть журнали до видалення гри або очищення її даних.

## Збирання

У Unity 6000.6.2f1: **Tools → Quiet Camp → Build Android Session Logs APK**.
Batch entry: `QuietCamp.Editor.QuietCampBuild.BuildAndroidSessionLogs`.
Результат: `QuietCamp/Builds/Android/QuietCamp-session-logs.apk`.
Використовується release-профіль з додатковим `QC_SESSION_LOGS`, без `QC_TEST`.
Звичайні release/dev entry points не вмикають запис сеансів.
Не запускайте другу Unity-сесію паралельно і не переривайте чужий ADB.

Підготовка APK сама по собі не підтверджує роботу експорту чи Pro на телефоні.
Google Play Review залишається непідтвердженим до перевірки придатної
Android-збірки на пристрої. Ця збірка не публікується в Google Play.

## Фактичний результат 2026-10-23

- APK зібрано з `main` (`29fb709c`): Unity 6000.6.2f1, IL2CPP, ARM64,
  версія гри 0.1.0, Android 8+ (API 26), target API 35. Розмір: 223 656 182 байти.
- SHA-256: `06f00f5b78390b0ed3322f039d2d340e2d15726d4a0d656b9a67741d24b8e9cc`.
- 181 C#-тест виконано на .NET із платформними підмінами; не Android runtime.
  13 перевірок owner-конфігурації пройшли.
- Перевірено фактичні player defines: `QC_SESSION_LOGS` є, `QC_TEST` немає.
  У метаданих готового APK присутні класи запису JSON та експорту.
- Підпис APK v2 валідний. Zip alignment 16 КБ пройшов; усі 17 ARM64-бібліотек
  мають ELF LOAD alignment не менше 16 КБ.
- Маніфест готового APK перевірено: стандартний FirebaseInitProvider видалено,
  власний privacy provider присутній у DEX, правила початкової заборони збору
  даних збережено. Ця перевірка не доводить відсутність мережевого трафіку.
- Збірка завершилася з `BuildResult.Succeeded`, проте Unity BuildReport показав
  2 errors і 2 warnings. У журналі є несумісність **Odin Editor** з
  `UnityEngine.EntityId.MagicVersion`, повідомлення headless GPU і попередження
  про iOS-плагін Google Ads. Це не звіт про чистий production-реліз.
- Для проходження фактичної Java-компіляції виправлено classpath дочірнього
  `QuietCampPrivacy.androidlib`: він отримує ті самі Billing/AndroidX залежності
  з чинного `PlayBillingDependencies.xml`. Платежі не активовано.
- У локальному кеші VFX 17.6.0 відновлено відсутній `.meta` для класу міграції
  з [офіційного Unity Graphics](https://github.com/Unity-Technologies/Graphics/blob/master/Packages/com.unity.visualeffectgraph/Runtime/Utilities/Playables/VisualEffectActivationDeprecated/VisualEffectActivationTrackMigration.cs.meta).
  Інсталяцію Unity не змінено. При очищенні кешу цей дефект пакета може повторитися.

На телефон APK не встановлювали. Створення файлів, експорт через MediaStore,
вхід Pro, повторний запуск та FPS на реальному Android ще не перевірені.
Службові результати перевірок і повний build log лежать в ігнорованому `Temp/ai/`.
