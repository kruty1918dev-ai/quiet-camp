# Quiet Camp: аудит заробітку без нав’язливої реклами

2026-10-21. Авторитетний стан: main 030e76d. Новий напрям власника: основна аудиторія 13+, молодші можуть фактично користуватися грою; монетизація — мета продукту. Пакет families із межею 18+ та миттєвим безкоштовним життям відкликано. Це не оновлення, яке слід встановлювати.

## Рекомендована основа економіки

Зберегти 100 рівнів основної кампанії, 5 стартових життів, 3 підказки, покарання за помилки та існуючий Pro без ресурсних лімітів. Не давати безмежних миттєвих безкоштовних поновлень. Стійка модель: повільне відновлення життів із часом, добровільне відео для негайної додаткової спроби, відео за потрібну зараз підказку, разова купівля Pro без очікування/лімітів. У кандидатові реалізовано 30 хв/життя до запасу 5 та відео за підказку до 5/UTC-добу. Це початковий налаштовуваний баланс, не результат виміряної конверсії або playtest. Покупка не повинна вимагати згоди на Firebase або рекламу.

Чому потрібна альтернатива очікування: повний безстроковий блок нормальної гри після відмови від rewarded відео створює проблеми за вимогами Google та добровільністю consent. Таймер зберігає цінність негайного рекламного/платного продовження, на відміну від миттєвої безкоштовної кнопки. Не погіршувати головоломки штучно для продажу життів; не продавати виправлення незрозумілих правил.

## Рекламні точки за пріоритетом

1. Додаткове життя: явна кнопка з точною нагородою в ресурсній панелі, коли гравець сам її відкрив. Не запускати відео автоматично після помилки. Показати також час відновлення й фактичну ціну Pro, якщо він реально продається.
2. Підказка: коли гравець натиснув підказку й вичерпав запас. Одне відео → одна точно описана підказка. Не забирати підказку, якщо нагорода збереглася невдало; повторювати grant без нового перегляду після успішного reward.
3. Косметичне оформлення власного табору/альбому: кілька справжніх доступних предметів із прозорим способом отримання, не випадкова нагорода і не нова валюта без потреби. Зараз є лише ліхтарик; потрібні реальні асети та художнє приймання.
4. Pro: спокійний рядок у ресурсах/налаштуваннях, не popup після кожної помилки. Чіткі права, локальна ціна від Google, відновлення покупки, pending/cancel/refund handling. Спочатку завершити Billing; не малювати фальшивий магазин.
5. Окремі завершені подорожі: природна точка після розділу/кампанії. Не вилучати вже безкоштовні 100 рівнів, не продавати архівний/неприйнятий контент. Уточнити, чи Pro включає майбутні DLC: поточна IsPro логіка може це припускати.

Для першого релізу не рекомендую банери, app-open ads, автоматичні interstitial і rewarded interstitial: вони порушують атмосферу та додають ризик випадкових натискань. Це рекомендація для цього cozy-пазла, не універсальне твердження про неефективність цих форматів.

## Вік, приватність і дохід

Основна аудиторія — 13+, а не автоматично дитяча або 18+. Google оцінює реальний контент і маркетинг, тому інтерес молодших не можна приховати декларацією. Для відомого віку до 13 й невідомого віку: жодного автоматичного tracking/рекламного запиту. Спеціальна child-serving модель для них — окреме продуктове рішення, не причина вимикати монетизацію для решти.

- 16–17: відновити доступний у main незалежний рекламний вибір та Teen treatment; не вимагати Analytics/Crashlytics для реклами. NPA з належними UMP/storage/vendor рішеннями. Юридична застосовність залежить від ринку; це не універсальна вікова межа всіх держав.
- 18+: той самий NPA шлях без непотрібної заборони реклами. Відмова від Analytics не вимикає AdMob. Персоналізація для першого релізу не потрібна для самого існування доходу.
- 13–15: відсутність особистої згоди на consent-based tracking не означає автоматичної заборони будь-якої реклами. У кандидатові реалізовано окремий, поки не активований Limited Ads шлях зі строгим віковим treatment, мінімальними даними й законною підставою. Не підміняти згоду неповнолітнього галочкою. Також оцінити обмежений режим для 16+/дорослих, які відмовили в tracking.

Google Limited Ads зменшує персоналізацію/ідентифікатори, але все ще використовує IP і доставляє/кешує рекламу. Programmatic Limited Ads додає anti-fraud cookies/local storage та увімкнений у Google за замовчуванням. Google покладає юридичну відповідальність за таке використання на видавця; це не автоматичний виняток із §25 TDDDG. Без programmatic demand дохід/заповнення можуть бути суттєво іншими. Упровадження потребує доказів режиму, фактичного аккаунта, належної інформації/правової оцінки та мережевих перевірок. Не обіцяти дохід від 13–15 до цієї перевірки.

## Показники для рішень

Відстежувати за наявними законними даними AdMob/Play: запити → match/fill → показ → reward → збережена нагорода, дохід на активного користувача, частоту показів, paid conversion/refunds. Додаткова gameplay Analytics незалежна й добровільна. Не робити її умовою реклами/гри/покупки. Немає власних вимірів DAU, retention, eCPM або конверсії, тому суми доходу зараз можуть бути лише сценаріями, не прогнозом.

## Що змінив кандидат після аудиту main

Стан таблиці вище описує main до патча. Кандидат додає AdHintService, повільне відновлення, окремі NPA/Teen, LTD та умовну персоналізацію лише дорослим; прибирає помилкову межу 18+ і миттєве безмежне продовження. Виправлено Pro-фільтр для всіх рекламних місць та різний формат revision/hash у першому запуску. Читання політики не дає згоди. Analytics і Crashlytics залишаються незалежними від реклами. Реальний Billing не підключений; продукт не продається. Виробничі IDs та підтвердження консолей не вигадані й залишені закритими.

Новий Unity IAP 5.4.4 окремо досліджено, але не встановлено: документація 5.4+ описує додаткові Unity Installation/Player/Session IDs та інші дані. Додавати цей SDK до дитячого/підліткового релізу лише заради видимості готового Pro без аудиту нових даних, реального товару й перевірки покупок було б некоректно. Перший рекламний реліз не потребує продажів Pro. Для Pro потрібен окремий реальний Billing-провайдер із серверною перевіркою/acknowledgement, відновленням та refund handling, а не published=true для qa.pro. Джерело: https://docs.unity.com/en-us/iap/privacy-and-consent/overview .

app-ads.txt раніше не знайдено. У сайті додано генератор `npm run admob:publisher -- pub-<реальні 16 цифр>`; без реального ID файл не публікується. Це не перемикач реклами. Перевірити developer website у Play та статус сканування у AdMob: https://developers.google.com/admob/android/app-ads .
